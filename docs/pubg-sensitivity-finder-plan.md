> 작성일: 2026-10-18 (v0.1 → v0.2)
> 상태: 기획 초안 (구현 전)
> 대상: PC 배틀그라운드(PUBG: BATTLEGROUNDS) 마우스 유저, **개인용 도구 (사용자 1명)**
> v0.2 변경 요약: 개인용으로 범위 축소(공유·DB·프로 DB 삭제), 계산 상수를 "미정"으로 수정, 단계 순서 변경(조준경 → 수직), 설정 용어표 추가, 이분법·체감 입력 방식 재설계, 소요 시간 재산정, 앵글 손잡이 삭제 반영

## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **단계별 체크리스트 위저드**로 묶어,
내가 훈련장에서 정해진 테스트를 하고 결과(명중 수, 탄착군)를 입력하면
**일반 감도 → 조준/조준경 감도 → 수직 감도** 순으로 내 감도를 수렴시켜 주는 개인용 웹 도구.

원칙: 계산(cm/360, 배율 변환)은 보조 수단이다. 공식은 전부 "추정"으로 취급하고, 최종 판단은 항상 인게임 테스트 결과로 한다.

## 2. 리서치 정리: 시중에 퍼진 감도 찾는 방법

### 2-1. 공통 전제 (거의 모든 자료가 동의)
1. **DPI 먼저 고정**(400 또는 800). 이후 바꾸지 않는다.
2. 마우스 가속 OFF, Windows 포인터 속도 기본(6/11).
3. 감도는 **한 번에 하나만**, 작은 폭으로 바꾼다.
4. 정한 값은 **최소 1주일 유지**한 뒤 재평가한다.
5. 기준 단위는 슬라이더 숫자가 아니라 **cm/360**.

### 2-2. 찾는 순서
- 인벤 "감도 찾는 배린이가 봐야 할 인게임 감도 설정 방법": 좌우 대략 → 수직 → 좌우 섬세. 1~2사이클.
  - ⚠️ 이 순서는 조준경 값이 일반과 같은(통일) 전제에서만 성립한다. 수직 배율 체감은 "배율 감도 × 수직 배율"이므로 **배율 감도를 먼저 정해야** 수직 결과가 유효하다. v0.2는 일반 → 조준/조준경 → 수직 순서를 쓴다.

### 2-3. 일반(좌우) 감도 찾는 테스트
| 출처 | 방법 | v0.2 채택 |
|---|---|---|
| 영어권 가이드 (clip.dor.gg 등) | 이동 표적 **트래킹**: 오버슈트하면 ↓, 못 따라가면 ↑ | 채택 (명중 수로 측정) |
| 영어권 가이드 | 두 표적 사이 **플릭 왕복**: 오버/언더 방향으로 조정 | 채택 (한 번에 멈춘 횟수로 측정) |
| 에임트레이너 커뮤니티 (PSA 방식) | **이분법**: 두 후보 중 편한 쪽을 고르고 범위를 절반씩 좁힘 | 채택 (블라인드 A/B로 변형) |
| 인벤 "감도찾기에 대한 모든 노하우" | 엄폐물 뒤 앉아 **중앙 집탄**, 좌우로 벌어지면 ↓ | **참고 지표로 격하.** 배그 좌우 반동은 확률적이고 손잡이·보정기로 억제되어 감도 신호가 약함 |
| 보텍스게이밍 | 차량 사격장에서 좌우 최종 점검 | 선택 단계 |

### 2-4. 수직 배율 찾는 테스트
| 출처 | 방법 | v0.2 채택 |
|---|---|---|
| 인벤 "수직감도 맞추기" | 10발 쏴서 **상탄이 많으면 +0.05**, 아래로 쉽게 꺾이면 ↓. 폭 0.05~0.1 | 채택 |
| 보텍스게이밍 | 앵글 손잡이로 좌우 반동 제거 후 수직만 평가 | **앵글 손잡이가 게임에서 삭제되어 사용 불가.** 대체: 내가 실제로 쓰는 손잡이 세팅으로 쏘고 **세로 분포만** 평가(좌우는 무시). 좌우 노이즈를 줄이려면 하프 손잡이 사용 |
| clip.dor.gg | 4배율로 10/20/30발 버스트 집탄 비교 | 채택 |
| 프로 통계 (blast.tv 기사 1건) | 프로 다수가 수직 배율 1.0 | 시작값 1.0에만 사용. 비율 수치는 표본 불명이라 인용하지 않음 |

### 2-5. 조준·조준경 감도
| 출처 | 방법 | v0.2 채택 |
|---|---|---|
| 보텍스게이밍 | 이동 표적을 조준 상태로 좌우 트래킹. 못 따라가면 ↑, 버벅이면 ↓ | 채택 |
| 인벤 | 통일파(전부 일반과 동일) vs 분리파(조준 -1, 2x -2, 4x~15x -4) | 두 프리셋으로 제공. 어느 쪽이 "추천"이라는 서술 없음 |
| clip.dor.gg | 4배율로 30초 조준 유지, 흔들리면 그 배율만 ↓ | 채택 |
| mouse-sensitivity.com 포럼 (DPI Wizard 답글 1건) | PUBG는 내부적으로 모니터 거리 수평 100%(MDH 100%)로 배율을 스케일링 | **미검증 주장.** Phase 0에서 일반/조준경/4x 각각 cm/360 실측으로 게임 내장 스케일링 방식을 역산한 뒤 분리 모드 공식에 반영 |

### 2-6. 참고 수치의 신뢰도
출처마다 cm/360 권장 범위가 다르고(aiming.pro 22~38cm, 커뮤니티 30~45cm, mouse-sensitivity.com 20~80cm), 슬라이더 ↔ cm/360 변환 상수가 확정되지 않았으므로 **v0.2에서는 어떤 cm/360 수치도 시작값 계산에 쓰지 않는다.** 시작값은 §4 Step 1 규칙(현재 감도 우선)으로 정한다. 프로 세팅 값(curexi 등)은 "참고 링크"로만 남긴다.

### 2-7. PUBG 감도 수학 (전부 추정)
- cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각)
- PUBG 슬라이더(0~100)는 선형이 아니라 **지수형**으로 보인다. ini의 `LastConvertedMouseSensitivity`와 슬라이더의 관계로 커뮤니티가 추정한 식: `LastConverted = 0.002 × 10^(슬라이더/50)`. 즉 **+50 = 10배, +1 ≈ ×1.047**.
  - `LastConverted`는 UE4 내부 계수이며 **"카운트당 회전각(도)"이라는 근거는 없다.** 따라서 cm/360을 얻으려면 별도의 스케일 상수 C가 필요하고, C는 미정이다.
  - 조준경·배율은 별도 상수를 가지는 것으로 보고됨(조준경 50 → 0.00429).
  - 1인칭 FOV가 힙파이어 cm/360에 영향을 주는지도 미확인.
- 프로그램은 **"지수형 슬라이더(+1 ≈ ×1.047)"라는 형태 가정만** 상대 변환에 쓰고, 절대값(cm/360)은 Phase 0 실측 또는 Step 2 실측으로만 표시한다.
- ini 위치: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의 (개인용)

### 3-1. 내가 해결하려는 것
- 유튜브 방법을 따라 하다가 **어디까지 했는지 잊는다** → 단계·회차·입력값을 전부 기록하는 체크리스트.
- 감도를 **감으로 끝없이 바꾼다** → 이분법으로 정해진 회차 안에 결정하고, 1주일 잠금.
- 설정을 바꿀 때마다 **배율별 값을 다시 계산**해야 한다 → 상대 변환기(통일/분리 프리셋).

### 3-2. 범위 (v1)
- 포함: 일반 / 조준 / 조준경 / 배율 6종 / 수직 배율, 통일·분리 모드, 훈련장 테스트 체크리스트와 타이머, 결과 카드, JSON 내보내기/불러오기, 측정 히스토리(로컬).
- 제외: 공유 링크, 서버 저장, 프로 DB·퍼센타일, 타 게임 변환, PUBG 모바일, 마우스 입력 자동 측정, 브라우저 푸시 알림.

### 3-3. 모드
| 모드 | 포함 단계 | 예상 소요 |
|---|---|---|
| **퀵 모드 (기본, Phase 1 MVP)** | Step 0 간소 → Step 3 이분법 3회차(테스트 2종) → Step 4 조준경 프리셋 적용(테스트 생략) → Step 6 결과 | 25~35분 |
| 풀 모드 | 전 단계 + Step 2 실측 + Step 4 배율별 테스트 + Step 5 수직 + Step 6 점검 | 90~150분 (2회로 나눠서 해도 됨) |

## 4. 사용자 흐름

```
[0 준비] → [1 시작점] → [2 cm/360 실측 (선택)] → [3 일반 감도 이분법]
   → [4 조준/조준경/배율] → [5 수직 배율] → [6 결과 카드 + 1주일 잠금]
```

각 단계는 "① 인게임에 넣을 값 → ② 훈련장에서 할 일 체크리스트(타이머) → ③ 결과 입력(셀 수 있는 지표) → ④ 다음 값" 구조로 통일한다.

### Step 0. 준비 (5분)
입력:
- DPI (400/800/1600/직접) + "지금부터 고정" 체크
- 주 시점 (3인칭 / 1인칭 / 둘 다) 와 1인칭 FOV
- 마우스패드 가로 길이(cm) — Step 2 기준 거리와 감도 상한에 사용
- **현재 감도 전부** (일반/조준/조준경/배율 6종/수직/통일 토글) — 직접 입력 또는 ini 업로드(Phase 0 대응표가 있을 때만 활성)
- 내가 실제 쓰는 무기 세팅 (예: M416 + 보정기 + 하프 손잡이 + 4배율) — 수직 배율 테스트는 이 세팅으로 한다

체크리스트: 마우스 가속 OFF, Windows 포인터 속도 기본, 훈련장 입장, 테스트 위치 메모(이동 표적 레일 위치, 플릭용 두 표적 간 거리 — 처음 한 번 내가 정해서 저장).

### Step 1. 시작점 (자동)
우선순위: **현재 일반 감도(있으면)** > Step 2 실측값에서 역산 > 기본값 50.
- cm/360 참고 범위는 쓰지 않는다(§2-6).
- 시작값 S는 "임시"로 표시.

### Step 2. cm/360 실측 (선택, 10분)
목적: 내 환경에서 "일반 S일 때 cm/360"을 한 번 측정해 두면, 이후 모든 값에 cm/360을 함께 표시할 수 있다(지수형 가정으로 상대 환산).
절차:
1. 기준 거리 D = 패드 가로 길이 또는 A4 긴 변(29.7cm). 마우스 시작·끝 위치에 테이프.
2. 훈련장에서 정면 지형물 조준 → 마우스를 D만큼 수평 이동 → **정반대(180°) 지형물**이 정면에 왔는지 확인. 180° 기준이라 패드가 짧아도 가능.
3. 입력: "180°보다 더 돌았다 / 덜 돌았다 / 거의 맞다" + 체감 비율(예: 약 1/4 더). 2~3회 반복해 평균.
4. 결과: cm/360 ≈ 2 × D × (180 / 실제 회전각). 오차 ±10% 표기. 이 값 하나로 사용자 상수 C를 정한다.
건너뛰면 cm/360 표시는 꺼지고 슬라이더 값만 다룬다.

### Step 3. 일반 감도 이분법 (핵심, 퀵 30분 / 풀 50분)
설계 원칙: **블라인드 A/B, 순서 무작위, 셀 수 있는 지표.**
1. 범위 초기화: `lo = S × 1/1.58 (슬라이더 -10)`, `hi = S × 1.58 (+10)`. 두 후보 A/B는 lo, hi에 대응하지만 **숫자는 숨긴다**(종료 후 공개). 어느 쪽을 먼저 할지는 무작위.
2. 후보 하나당 테스트 세트 (약 5분, 감도 변경 왕복 1분 포함):
   - 플릭: 두 표적 왕복 10회 → **한 번에 멈춘 횟수(0~10)** 입력
   - 트래킹: 이동 표적 좌우 따라가며 15초 사격 → **명중 수** 입력(훈련장 명중 표시 이용)
   - (풀 모드만) 집탄 20발 → 참고용, 점수에 가중치 0.
3. 두 후보 점수 비교 → 높은 쪽으로 범위를 절반 좁힘. 점수가 같으면 "동률" 처리.
4. 상태 머신 규칙:
   - `select_high` / `select_low`: 선택 쪽으로 반감
   - `widen`: 같은 방향 극값을 **2회 연속** 선택하면 범위를 그 방향으로 2배 확장(초기 추정이 틀린 경우 탈출)
   - `tie`: 범위 중앙값 채택 후 종료 후보. 동률 2회면 종료
   - `undo`: 이전 회차로 복원
   - 종료: 범위 폭 ≤ 슬라이더 2, 또는 동률 2회, 또는 최대 6회차
5. 결과: 일반 감도 확정. 동률 종료 시 기본은 **중앙값**이며, "높은 쪽/낮은 쪽 선호" 옵션으로 바꿀 수 있다(인벤의 "높은 쪽" 규칙은 옵션).
   - 산술: 폭 20에서 시작해 3회 반감하면 폭 2.5, 4회면 1.25. widen이 없으면 4회에 종료.

### Step 4. 조준·조준경·배율 (퀵 2분 / 풀 30분)
1. 모드 선택 (둘 다 성향 문제, 추천 없음):
   - **통일 모드**: 통일 토글 ON, 조준·조준경 = 일반. 배율은 게임이 자동 적용.
   - **분리 모드**: 통일 토글 OFF. 프리셋 A "커뮤니티형"(조준 -1, 조준경 -1, 2x -2, 3x~15x -4) / 프리셋 B "0% 초점거리형"(Phase 0에서 게임 내장 스케일링을 확정한 뒤 활성화) / 직접 입력.
2. 퀵 모드는 프리셋 값을 그대로 결과에 넣고 끝.
3. 풀 모드 테스트 (조준경 → 4x → 8x 순, 나머지는 보간):
   - 이동 표적 조준 트래킹 15초 → 명중 수. 두 후보(현재값, 현재값-2) 비교.
   - 4x로 표적 30초 조준 유지 → 흔들림 "있다/없다". 있으면 그 배율만 -1~-2.
   - 통일 모드에서 특정 배율을 바꾸게 되면 **자동으로 분리 모드로 전환**하고 "통일 토글 OFF" 안내.
4. 보간 규칙: 테스트한 배율 사이는 `log10(배율)` 축에서 슬라이더 선형 보간. 15x는 8x 규칙을 그대로 따름. 2x·3x는 조준경과 4x 사이를 보간.
5. 결과: 조준, 조준경, 배율 6종, 통일 토글 상태. **이 값들을 확정한 뒤에 Step 5로 간다.**

### Step 5. 수직 배율 (15분)
전제: Step 4에서 4배율 값이 확정된 상태. 4배율 값을 나중에 바꾸면 이 단계를 다시 한다(앱이 경고).
1. 시작값 1.0. 무기는 Step 0에서 적은 **내 실제 세팅**(앵글 손잡이는 삭제됐으므로 사용하지 않음. 좌우 노이즈를 줄이려면 하프 손잡이). 4배율, 거리 10~15m, 서서 사격.
2. 10발 → 20발 → 30발 사격. 입력: 세로 분포만 본다. "위로 튄다(상탄) / 아래로 꺾인다(하탄) / 세로로 모임". 좌우 벌어짐은 무시.
3. 상탄 → +0.05, 하탄 → -0.05. 두 방향을 한 번씩 왕복하면 중간값으로 종료. 최대 4회.
4. 결과: 수직 배율. 측정 조건(배율, 그 배율의 감도, 무기 세팅)을 함께 기록.

### Step 6. 결과 카드 + 1주일 잠금 (5분)
- 설정표: 일반 / 조준 / 조준경 / 2x·3x·4x·6x·8x·15x / 수직 배율 / 통일 토글. 인게임 입력 순서대로 나열.
- Step 2를 했으면 cm/360(±오차)과 "한 바퀴에 패드의 몇 %" 표시.
- 측정 조건 기록: DPI, 시점, FOV, 무기 세팅, 게임 버전(직접 입력), 날짜.
- **잠금**: 7일 동안 "변경 금지" 배지. 재방문 시 "N일 경과" 표시. 7일 후 "재평가" 버튼이 활성화되어 Step 3 축소판(2회차)으로 재진입.
- JSON 내보내기/불러오기. 히스토리 목록(날짜별 설정표 비교).
- 선택 점검: 차량 사격장 좌우 트래킹 15초 명중 수 기록(결과 카드에 메모로).

## 6. 계산 엔진 설계

```
형태 가정 (상대 변환에만 사용):
  ratio(Δslider) = 10^(Δslider/50)                 // +1 ≈ ×1.047, +50 = ×10
  Δslider(배수 m) = 50 × log10(m)

절대값 (Step 2 실측이 있을 때만):
  cm360(S0) = 실측값                                // Step 2
  cm360(S)  = cm360(S0) / ratio(S - S0)             // 지수형 가정으로 환산, 오차 ±10% 표기

분리 모드 프리셋:
  A 커뮤니티형: 고정 오프셋 표 (조준 -1, 조준경 -1, 2x -2, 3x~15x -4)
  B 0% 초점거리형: Δslider = 50 × log10( m_목표(배율) / m_내장(배율) )
     m_목표 = tan(fov_배율/2) / tan(fov_힙/2)        // 배율별 FOV 실측 테이블 필요
     m_내장 = 게임이 이미 적용하는 배수 (Phase 0에서 역산)  // 미정이면 프리셋 B 비활성

보간: log10(배율) 축에서 슬라이더 선형 보간. 15x = 8x 규칙.
```
- 모든 상수는 `src/lib/sens/constants.ts`에 모으고 `{ value, status: '추정'|'실측', source, measuredAt }` 형태로 둔다.
- v0.1의 `k × 0.002 × 10^(slider/50)`을 회전각으로 쓰는 식은 **삭제**. 절대값은 실측에서만 나온다.

## 7. 기술 설계

- **스택**: Next.js 14 App Router, TypeScript, Tailwind (레포와 동일). 서버 코드 없음(정적 클라이언트 페이지).
- **라우트**: `src/app/(sens)/sens/` 라우트 그룹에 자체 `layout.tsx`·metadata·다크 테마. `src/lib/sens`는 `src/data/profile.ts` 등 링크나무 코드를 import하지 않는다.
- **컴포넌트** `src/components/sens/`: `Wizard`, `StepCard`, `Checklist`, `Timer`, `AbPicker`(블라인드), `ScoreInput`, `ResultCard`, `HistoryList`.
- **도메인** `src/lib/sens/`: `math.ts`, `bisect.ts`, `presets.ts`, `storage.ts`(schemaVersion 포함, 마이그레이션), `iniParser.ts`(P2), `constants.ts`.
- **bisect 상태**: `{ lo, hi, round, history: Round[], mode: 'quick'|'full', pending: {aValue, bValue, order} }`
  전이: `select_high | select_low | tie | widen | undo | finish`. 종료 조건은 §4 Step 3-4.
- **저장**: localStorage 키 `sens:v1:*`, `schemaVersion` 필드. 내보내기는 JSON 파일 다운로드, 불러오기는 파일 선택.
- **테스트**: vitest 추가. `math.ts`(ratio/Δslider 왕복, 보간 경계), `bisect.ts`(전이표 전부, widen·undo·종료), `storage.ts`(마이그레이션). 위저드 해피패스는 Playwright 1개(퀵 모드 완주, 중단 후 재개).
- **폰 사용성**: 큰 버튼, 타이머 소리, Wake Lock API(iOS Safari 제한은 "화면 자동 잠금 끄기" 안내로 대체).

## 8. 검증 계획

### Phase 0 — 실측 스파이크 (구현 전, 1~2일)
- [ ] **설정 화면 캡처**: 현재 패치의 감도 메뉴 전체 항목 이름·범위·토글. §1-1 용어표 확정. 카메라 감도 항목 존재 여부 확인.
- [ ] **ini 필드 목록**: `GameUserSettings.ini`의 감도 항목 이름 추출. 슬라이더 0~100(5단위) ↔ `LastConverted` 대응표 작성.
- [ ] **cm/360 실측**: 800 DPI 고정, 일반 20/35/50/65/80에서 각각 측정 → 지수형(+1 ≈ ×1.047) 형태가 맞는지 확인. 가능하면 자 대신 스크립트(AutoHotkey 등)로 정확한 카운트 수를 보내 측정.
- [ ] **내장 스케일링 역산**: 일반 50 / 조준경 50 / 4x 50에서 cm/360 측정 → 게임이 배율에 적용하는 배수가 0% / MDH 100% / 기타 중 어디에 가까운지 확인. 프리셋 B 활성화 여부 결정.
- [ ] **1인칭 FOV 영향**: FOV 80/90/103에서 일반 50의 cm/360 변화.
- [ ] **훈련장 콘텐츠 확인**: 이동 표적 레일 위치, 명중 표시 방식, 플릭용 두 표적 선정, 차량 사격장 유무. 테스트 위치를 Step 0 메모 기본값으로.
- [ ] **손잡이 현황**: 현재 패치의 손잡이 종류와 효과(하프/수직/라이트/엄지) 확인. Step 5 안내 문구 확정.

### 자가 테스트
- 퀵 모드 1회 완주 → 실제 소요 시간으로 §3-3 수치 교정.
- 풀 모드 1회 완주 → 단계별 소요·막힌 지점 기록.
- 7일 잠금 후 재평가 1회 → 재진입 흐름 검증.

## 11. 열린 질문
1. 통일 토글이 정확히 무엇을 통일하는지 (조준경 값을 배율에 복사? 일반 값을?) — Phase 0.
2. 카메라 감도 항목이 별도로 존재하는지, 1인칭/3인칭이 다른 값을 쓰는지 — Phase 0.
3. 레포를 링크나무와 계속 같이 둘지, 정적 페이지로 분리할지 — 구현 규모가 커지면 분리.
4. 훈련장에 명중 수를 셀 수 있는 표시가 있는지. 없으면 트래킹 지표를 "따라간 시간(초)" 자가 평가로 대체.
