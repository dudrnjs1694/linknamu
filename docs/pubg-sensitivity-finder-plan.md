# 배틀그라운드 감도 찾기 프로그램 기획서 (v0.3)

> 작성일: 2026-10-18 (v0.1 → v0.2 → v0.3)
> 상태: 기획 초안 (구현 전)
> 대상: PC 배틀그라운드(PUBG: BATTLEGROUNDS) 마우스 유저, **개인용 도구(사용자 1명), PC방 플레이 환경**
> v0.3 변경 요약: PC방 환경 반영(설정 비영속·자리별 마우스 차이·시간 과금·폰↔PC 데이터 이동), "블라인드 A/B" 삭제 후 교차 반복+객관 지표+동률 임계값으로 교체, 이분법 전이표 작성(정수 슬라이더), 명중 수 측정 가능성을 구현 게이트로 격상(P0는 플릭 지표만), Step 2를 각도 고정·거리 측정으로 교체, 상수·시간·프리셋을 §6 한 곳으로 통합, 레이아웃 전략 명시

## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **단계별 체크리스트 위저드**로 묶어,
내가 PC방 훈련장에서 정해진 테스트를 하고 결과(플릭 성공 횟수, 탄착군)를 폰에 입력하면
**일반 감도 → 조준/조준경/배율 → 수직 배율** 순으로 내 감도를 수렴시키고,
다음 PC방 방문 때 **그 설정을 1분 안에 복원**할 수 있게 해 주는 개인용 웹 도구.

원칙: 계산은 보조 수단이다. 공식은 전부 "추정"으로 취급하고, 최종 판단은 인게임 테스트 결과로 한다.

## 2. 리서치 정리: 시중에 퍼진 감도 찾는 방법

### 2-1. 공통 전제 (거의 모든 자료가 동의)
1. **DPI 먼저 고정**(400 또는 800). PC방에서는 "고정"이 어려우므로 cm/360을 기준으로 삼고 매 방문 확인한다.
2. 마우스 가속 OFF, Windows 포인터 속도 기본(6/11).
3. 감도는 **한 번에 하나만**, 작은 폭으로 바꾼다.
4. 정한 값은 **최소 1주일 유지**한 뒤 재평가.
5. 기준 단위는 슬라이더 숫자가 아니라 **cm/360**.

### 2-2. 찾는 순서
- 인벤 "감도 찾는 배린이가 봐야 할 인게임 감도 설정 방법": 좌우 대략 → 수직 → 좌우 섬세.
  - ⚠️ 이 순서는 배율 값이 일반과 같은(통일) 전제에서만 성립. 수직 배율 체감은 "배율 감도 × 수직 배율"이므로 **배율 감도를 먼저 정한다.** v0.3 순서: 일반 → 조준/조준경/배율 → 수직.

### 2-3. 일반(좌우) 감도 찾는 테스트
| 출처 | 방법 | v0.3 채택 |
|---|---|---|
| 영어권 가이드 (clip.dor.gg 등) | 두 표적 사이 **플릭 왕복**: 오버/언더 방향으로 조정 | **P0 핵심 지표.** "한 번에 멈춘 횟수"로 측정(정의 §6 M-1) |
| 영어권 가이드 | 이동 표적 **트래킹**: 오버슈트하면 ↓, 못 따라가면 ↑ | **P1.** 명중 수를 셀 수단이 확정된 뒤(§8 게이트) |
| 에임트레이너 커뮤니티 (PSA 방식) | **이분법**: 두 후보 중 나은 쪽으로 범위를 좁힘 | 채택. 전이표 §6 B |
| 인벤 "감도찾기에 대한 모든 노하우" | 엄폐물 뒤 앉아 중앙 집탄, 좌우로 벌어지면 ↓ | 참고 지표(가중치 0). 배그 좌우 반동은 확률적이고 손잡이·보정기로 억제되어 감도 신호가 약함 |
| 보텍스게이밍 | 차량 사격장에서 좌우 최종 점검 | 선택 |

### 2-4. 수직 배율 찾는 테스트
| 출처 | 방법 | v0.3 채택 |
|---|---|---|
| 인벤 "수직감도 맞추기" | 10발 쏴서 상탄이 많으면 +0.05, 아래로 쉽게 꺾이면 ↓ | 채택. 단, 적응 효과를 막기 위해 **각 값에서 첫 10발만 판정** |
| 보텍스게이밍 | 앵글 손잡이로 좌우 반동 제거 후 수직만 평가 | **앵글 손잡이 삭제로 사용 불가.** 대체: **항상 내 실제 무기 세팅**으로 쏘고 세로 분포만 판정(좌우 무시). 손잡이별 효과 수치는 미검증이므로 서술하지 않음 |
| clip.dor.gg | 4배율로 10/20/30발 버스트 | 10발 단위 채택 |
| 프로 통계 | 프로 다수가 수직 배율 1.0 | 시작값 1.0에만 사용. 비율 수치는 인용하지 않음 |

### 2-5. 조준·조준경 감도
| 출처 | 방법 | v0.3 채택 |
|---|---|---|
| 보텍스게이밍 | 이동 표적을 조준 상태로 트래킹 | 채택(P1, 명중 수 수단 확정 후). 그 전에는 **조준 플릭** 지표 사용 |
| 인벤 | 통일파 vs 분리파(조준 -1, 2x -2, 4x~15x -4) | 두 프리셋으로 제공(§6 P). 추천 없음 |
| clip.dor.gg | 4배율로 30초 조준 유지, 흔들리면 ↓ | **삭제.** 조준경 흔들림은 무기 애니메이션이라 감도와 무관 |
| mouse-sensitivity.com 포럼 (답글 1건) | PUBG는 MDH 100%로 배율 스케일링 | **미검증.** Phase 0 역산 후 프리셋 B에 반영 |

### 2-6. 참고 수치의 신뢰도
출처마다 cm/360 권장 범위가 다르고(aiming.pro 22~38cm, 커뮤니티 30~45cm, mouse-sensitivity.com 20~80cm) 변환 상수가 미확정이므로 **어떤 cm/360 수치도 시작값 계산에 쓰지 않는다.** 프로 세팅은 참고 링크로만.

### 2-7. PUBG 감도 수학 (전부 추정)
- cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각)
- PUBG 슬라이더(0~100)는 **지수형**으로 보인다. ini `LastConvertedMouseSensitivity`와 슬라이더의 관계로 커뮤니티가 추정한 식: `LastConverted = 0.002 × 10^(슬라이더/50)` → **+50 = 10배, +1 ≈ ×1.047** `{status: 추정, source: mouse-sensitivity.com 포럼 #8889}`
  - `LastConverted`는 UE4 내부 계수이며 회전각이라는 근거는 없다. 절대값(cm/360)은 실측에서만.
  - 조준경은 별도 상수 추정(조준경 50 → 0.00429) `{status: 추정, source: 같은 포럼 #607}`
  - 1인칭 FOV가 힙파이어 cm/360에 영향을 주는지 미확인.
  - 슬라이더가 정수 단위인지, 수직 배율의 입력 단위(0.01? 0.05?)는 Phase 0 확인.
- 프로그램은 **"지수형 슬라이더" 형태 가정만** 상대 변환(DPI 변경 환산, 프리셋, 보간)에 쓴다.
- ini 위치: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의 (개인용)

### 3-1. 해결하려는 것
- 유튜브 방법을 따라 하다 **어디까지 했는지 잊는다** → 단계·회차·점수를 폰에 기록.
- 감도를 **감으로 끝없이 바꾼다** → 이분법으로 정해진 회차 안에 결정, 7일 잠금.
- 설정을 바꿀 때 **배율별 값을 다시 계산**해야 한다 → 상대 변환기(프리셋).
- **PC방에서 매번 설정이 날아간다** → 복원 카드 + 세션 시작 점검.
- **자리마다 마우스가 다르다** → cm/360 기준 + DPI 변경 환산.

### 3-2. 범위 (v1)
- 포함: 일반 / 조준 / 조준경 / 배율 6종 / 수직 배율, 통일·분리 프리셋, 체크리스트·타이머, 이분법, 복원 카드, 세션 시작 점검, DPI 변경 환산, JSON 내보내기/불러오기, URL/QR 상태 이동, 히스토리.
- 제외: 공유, 서버 저장, 프로 DB, 타 게임 변환, PUBG 모바일, 마우스 입력 자동 측정, 푸시 알림.

### 3-3. 모드 (소요 시간은 §6 T 표에서 도출)
| 모드 | 포함 단계 | 합계 |
|---|---|---|
| **퀵 (기본, Phase 1 MVP)** | 0-A·0-B → 1 → 3(브래킷 1회 + 이분 2회, 플릭만) → 4 프리셋 → 6 | 약 45분 |
| 풀 | 전 단계. **단계 단위로 여러 방문에 나눠 진행** | 약 2시간 15분 (방문 2~3회) |
| 세션 점검 (매 방문) | 0-B만 | 3~5분 |

## 4. 사용자 흐름

```
매 방문: [0-B 세션 점검] → (복원 카드로 설정 입력) → 플레이
처음/재평가:
[0-A 준비] → [0-B 세션 점검] → [1 시작점] → [2 cm/360 실측 (선택)]
   → [3 일반 감도 이분법] → [4 조준/조준경/배율] → [5 수직 배율] → [6 복원 카드 + 7일 잠금]
```

각 단계: "① 인게임에 넣을 값 → ② 훈련장에서 할 일(타이머) → ③ 결과 입력(셀 수 있는 지표) → ④ 다음 값".
**숫자는 숨기지 않는다.** 내가 직접 설정에 입력하므로 블라인드는 불가능하다. 편향 대응은 §6 M의 교차 반복·객관 지표·동률 임계값으로 한다.

### Step 0-A. 준비 (처음 1회, 10분)
입력:
- 마우스: "내 마우스 가져감 / PC방 마우스" 선택. 내 마우스면 DPI 고정값(400/800/1600). PC방 마우스면 "오늘의 DPI"를 0-B에서 매번 확인.
- 주 시점(3인칭/1인칭/둘 다), 1인칭 FOV.
- **현재 감도 전부**(일반/조준/조준경/배율 6종/수직/통일 토글). 모르면 비움.
- 내가 실제 쓰는 무기 세팅(예: M416 + 보정기 + 수직 손잡이 + 4배율). Step 5는 이 세팅으로.
- 훈련장 테스트 위치 메모: 플릭용 두 표적(거리·간격), 정면/정반대 기준 지형물 쌍(Step 2용), 수직 테스트 거리(20~30m 표적). 처음 한 번 정해서 저장.
- 테이프 기준 거리 D(cm): 패드에 붙일 두 점 간 거리. A4 긴 변 29.7cm를 기본값으로 제안.

### Step 0-B. 세션 시작 점검 (매 방문, 3~5분)
체크리스트:
1. Windows 포인터 속도 6/11, "포인터 정확도 향상" OFF.
2. 마우스 DPI 확인: PC방 마우스면 DPI 버튼/소프트웨어로 확인하거나, 모르면 3번으로 판정.
3. **1바퀴 테스트**: 훈련장(또는 로비 캐릭터 회전으로 대체 가능 여부 Phase 0 확인)에서 복원 카드의 일반 감도를 넣고, 테이프 거리 D를 끌어 Step 2에서 기록한 회전각(360° 또는 180° 지형물 쌍)이 나오는지 확인. 
   - 맞으면 통과. 
   - 안 맞으면 "오늘 마우스 보정": 실제로 1바퀴가 되는 거리 D'를 재서 입력 → 앱이 `Δslider = 50 × log10(D'/D)`로 오늘용 일반 슬라이더를 계산(§6 D-2). 다른 항목은 같은 Δ를 적용. "오늘용 값"으로 표시하고 원본은 바꾸지 않음.
4. 복원 카드 순서대로 설정 입력 → 완료 체크.

### Step 1. 시작점 (자동)
우선순위: **현재 일반 감도(있으면)** > 기본값 50. 다른 입력은 쓰지 않는다.

### Step 2. cm/360 실측 (선택, 10분)
목적: 내 환경에서 "일반 S일 때 cm/360"을 한 번 측정해 두면 이후 모든 값에 cm/360을 표시하고, 0-B의 1바퀴 테스트 기준이 된다.
방법: **각도를 고정하고 거리를 잰다.**
1. 정면 기준 지형물을 조준한다. 마우스 위치에 테이프 1.
2. 마우스를 직선으로 천천히 끌어 **같은 지형물이 다시 정면에 올 때(360°)** 멈춘다. 테이프 2.
3. 테이프 1~2 거리를 자로 측정 = cm/360. 3회 반복해 평균, 편차 표기(자 눈금 ±0.5cm + 손 흔들림).
4. 패드가 짧아 360°가 안 되면 Step 0-A의 정반대(180°) 지형물 쌍을 쓰고 ×2.
결과: cm/360(S), 사용 거리 D와 각도(360/180) 저장. 건너뛰면 cm/360 표시는 꺼지고 0-B 3번은 "D를 끌어 이전과 같은 각도가 나오는지"로만 판정한다(각도 기록은 처음 방문에 자동 생성).
Phase 0의 AHK 측정은 "지수형 형태 검증"용, Step 2는 "내 환경 절대값"용으로 역할이 다르다.

### Step 3. 일반 감도 이분법 (핵심)
규칙은 전부 §6 B(전이표)와 §6 M(지표). 여기서는 흐름만.
1. **브래킷 회차**: `lo = S-10`, `hi = S+10`(정수, 1~100 클램프). 두 값을 각각 테스트(순서 무작위). 한쪽이 **강하게**(§6 M-3 임계) 이기면 그 방향으로 폭만큼 이동해 새 끝값만 추가 테스트(최대 2회). 아니면 이분 단계로.
2. **이분 회차**: `mid = round((lo+hi)/2)` 테스트(1회). 승자 끝값의 점수는 재사용. 승자 쪽 절반을 새 구간으로.
3. **동률**: 안쪽으로 1/4씩 축소해 두 끝값 재테스트. 동률 2회면 중앙값으로 종료.
4. **종료**: 구간 폭 ≤ 4, 또는 동률 2회, 또는 최대 회차 도달. 결과는 테스트한 값 중 **최고 점수 값**(퀵 모드도 동일).
5. 테스트 1회 = 설정 변경 왕복 + 플릭 10회(퀵) / 플릭 10회 × 2세트 교차(풀). 트래킹은 P1 활성 후 추가.
6. `undo`로 이전 회차 복원 가능.

### Step 4. 조준·조준경·배율
1. 모드 선택(둘 다 성향, 추천 없음):
   - **통일**: 통일 토글 ON(존재 시). 조준·조준경 = 일반. 배율은 게임이 적용.
   - **분리**: 토글 OFF. 프리셋 A(§6 P) / 프리셋 B(Phase 0 역산 후 활성) / 직접 입력.
2. 퀵 모드: 프리셋 값을 결과에 넣고 끝.
3. 풀 모드 테스트(조준경 → 4x → 8x 순, 최대 줌 고정):
   - 후보는 **양방향** (현재-2, 현재+2). 지표는 조준 상태 플릭(P0) 또는 트래킹 명중 수(P1). 비교 규칙은 §6 M.
   - 승자가 극값이면 같은 방향으로 한 번 더(±2). 최대 2회.
   - 통일 모드에서 특정 배율을 바꾸게 되면 **자동으로 분리 모드 전환** + "토글 OFF" 안내.
4. 보간(§6 I): 조준경=1x, 테스트한 배율 사이는 log10(배율) 축 선형, 15x는 **8x와 같은 슬라이더 값**.
5. 결과 확정 후 Step 5. 이후 4x 값을 바꾸면 Step 5 재측정 경고.

### Step 5. 수직 배율 (15분)
안내 문구: "수직 배율은 모든 조준 모드에 공통 적용된다. 기본 1.0 유지가 기본값이고, 이 단계는 1.0에서 벗어날 근거가 있는지만 확인한다. 1.0을 벗어나면 비조준 대각 플릭도 왜곡된다."
1. 시작값 1.0. **Step 0-A의 실제 무기 세팅**, 4배율(Step 4 확정값), 거리 20~30m, 서서 사격.
2. 각 후보 값에서 **첫 10발만** 판정(적응 효과 제한). 입력: 세로 분포 "상탄 / 하탄 / 모임". 좌우 무시.
3. 상탄 → +0.05, 하탄 → -0.05(입력 단위는 Phase 0 확인 후 조정). 방향이 한 번 뒤집히면 두 값의 중간(입력 단위로 반올림)으로 종료. 최대 4회.
4. 후보 순서는 무작위(1.0 → 1.05 → 0.95 식의 고정 순서 금지).
5. 결과: 수직 배율 + 측정 조건(배율, 그 배율의 감도, 무기 세팅, 거리).

### Step 6. 복원 카드 + 7일 잠금 (5분)
- **복원 카드**: 인게임 메뉴 순서대로 정렬(Phase 0 캡처 순서). 각 줄에 체크박스. 큰 글씨(폰을 옆에 두고 읽음). "오늘 마우스 보정"이 있으면 오늘용 값 열을 나란히 표시.
- 측정 조건: DPI(또는 "PC방 마우스, D=…cm 기준"), 시점, FOV, 무기 세팅, 게임 버전(직접 입력), 날짜.
- Step 2를 했으면 cm/360(±편차)과 패드 사용 비율.
- **잠금**: 7일 "변경 금지" 배지. 7일 후 "재평가" 활성 → Step 3 축소판(브래킷 없이 `±5`에서 이분 2회).
- JSON 내보내기/불러오기, **URL/QR 생성**(상태를 URL 해시에 압축 인코딩. PC 브라우저 ↔ 폰 이동용. 서버 없음).
- 히스토리: 날짜별 복원 카드 비교.
- 선택 점검: 차량 사격장 좌우 트래킹 메모.

## 6. 상수·규칙 단일 정의 (본문은 여기만 참조)

### 6-A. 상수 저장 형식
`src/lib/sens/constants.ts` 의 모든 값은 `{ value, status: '추정'|'실측'|'설정', source?, measuredAt? }`.

### 6-B. 이분법 전이표 (정수 슬라이더 공간)
상태: `{ lo, hi, phase: 'bracket'|'bisect'|'done', round, scores: Record<slider, Score>, tieCount, bracketShifts, history[] }`
파라미터: `W0 = 10`(초기 반폭), `W_END = 4`(종료 폭), `R_MAX_QUICK = 3`, `R_MAX_FULL = 6`, `SHIFT_MAX = 2`, 임계값은 §6 M-3.

| phase | 입력(비교 결과) | 조건 | 다음 상태 |
|---|---|---|---|
| 초기화 | — | — | `lo = clamp(S-W0)`, `hi = clamp(S+W0)`, 두 값 테스트(순서 무작위), phase=bracket |
| bracket | hi 강승 | bracketShifts < SHIFT_MAX | `lo = hi`, `hi = clamp(hi + 2·W0)`, 새 hi만 테스트, bracketShifts++ |
| bracket | lo 강승 | bracketShifts < SHIFT_MAX | `hi = lo`, `lo = clamp(lo - 2·W0)`, 새 lo만 테스트, bracketShifts++ |
| bracket | 약승 / 동률 / 이동 한도 도달 | — | phase=bisect (구간 유지) |
| bisect | — (회차 시작) | hi-lo > W_END | `mid = round((lo+hi)/2)` 테스트 |
| bisect | mid vs 승자끝값: mid 승 | — | 구간을 `[lo, mid]`(lo가 이전 승자) 또는 `[mid, hi]`(hi가 이전 승자)로. 끝값 점수는 재사용 |
| bisect | mid 패 | — | 구간을 승자 끝값 쪽 절반 `[mid, hi]` 또는 `[lo, mid]`로 |
| bisect | 동률 | tieCount+1 < 2 | `q = ceil((hi-lo)/4)`, `lo += q`, `hi -= q`, 두 끝값 재테스트, tieCount++ |
| bisect | 동률 | tieCount+1 ≥ 2 | phase=done, 결과 = round((lo+hi)/2) |
| any | — | hi-lo ≤ W_END 또는 round ≥ R_MAX | phase=done, 결과 = `argmax(scores)` (동점이면 중앙에 가까운 값) |
| any | undo | history 있음 | 직전 상태 복원 |

클램프 결과로 `lo == hi`가 되면 즉시 done. 테스트 횟수: 초기 2 + 브래킷 이동당 1 + 이분 회차당 1(동률 시 2).

### 6-C. 지표와 비교 규칙 (M)
- **M-1 플릭 점수**: 두 표적을 10회 왕복. "한 번에 멈춤" = 플릭 후 **첫 정지에서 조준점이 표적 몸통 안에 있고, 추가 보정 없이 1발 사격해 명중**. 0~10점.
- **M-2 트래킹 점수(P1)**: 이동 표적 15초 사격 명중 수. 측정 수단은 §8 게이트에서 확정(탄흔 스크린샷 / 인스턴트 리플레이 재생 / 훈련장 표시).
- **M-3 비교**: 지표별로 `|a-b| ≤ max(1, 0.15·max(a,b))` 이면 동률. 지표가 2개 이상이면 지표별 승패 다수결, 1:1이면 동률. **강승** = 동률 임계의 3배 이상 차이(플릭 10점 만점 기준 4점 이상).
- **M-4 교차 반복**: 퀵 = A·B 1세트(순서 무작위). 풀 = A·B·A·B 2세트, 점수 합산.
- **M-5 집탄**: 기록만, 가중치 0.

### 6-D. 변환 (D)
- **D-1 형태 가정**: `ratio(Δ) = 10^(Δ/50)`, `Δslider(m) = 50·log10(m)` `{추정}`
- **D-2 DPI/마우스 변경 환산**: 같은 cm/360을 유지하려면 `Δslider = 50·log10(D'/D)` (D' = 오늘 실제 1바퀴 거리, D = 기준 거리). DPI를 알면 `Δslider = 50·log10(DPI_기준/DPI_오늘)`. 모든 항목에 같은 Δ. 결과는 정수 반올림, "오늘용"으로 표시.
- **D-3 절대값**: Step 2 실측 `cm360(S0)`가 있을 때만 `cm360(S) = cm360(S0) / ratio(S-S0)` 표시, 편차 함께.

### 6-E. 프리셋 (P) — 단일 정의
| 항목 | 프리셋 A 커뮤니티형 (일반 대비 Δ) | 프리셋 B 0% 초점거리형 |
|---|---|---|
| 조준 | -1 | Phase 0 후 |
| 조준경(1x) | -1 | `50·log10(m_목표/m_내장)`, `m_목표 = tan(fov_배율/2)/tan(fov_힙/2)` |
| 2x | -2 | 〃 |
| 3x | -4 | 〃 |
| 4x / 6x / 8x / 15x | -4 | 〃 |
프리셋 A 출처: 인벤 분리파 글(§2-5). 3x를 -4로 둔 것은 "4x~15x -4" 규칙을 3x까지 확장한 **이 문서의 결정**.

### 6-F. 보간 (I)
축 = `log10(배율)`, 조준경 = 1x(0). 테스트한 점 사이는 슬라이더 선형 보간 후 정수 반올림. 15x = 8x와 **같은 슬라이더 값**. 테스트하지 않은 쪽 끝은 가장 가까운 테스트 점 값.

## 7. 기술 설계

- **스택**: Next.js 14 App Router, TypeScript, Tailwind. 서버 코드 없음.
- **라우트와 레이아웃**: 레포의 루트 `src/app/layout.tsx`(그라데이션 배경, 테마 스크립트)를 상속한다. `src/app/(sens)/sens/layout.tsx`는 `'use client'` 없이 전체 화면 컨테이너로 배경·폰트를 덮어쓰고, 다크 기본. localStorage 키는 `sens:` 접두어로 분리해 기존 `theme` 키와 충돌 없음. 멀티 루트 레이아웃 전환은 하지 않는다(기존 페이지 변경 최소화).
- **클라이언트 경계**: 위저드 전체는 `'use client'` 컴포넌트. localStorage 접근은 `useEffect` 이후(mounted 가드)로 하이드레이션 불일치 방지.
- **컴포넌트** `src/components/sens/`: `Wizard`, `StepCard`, `Checklist`, `Timer`, `CandidatePicker`(두 후보 순서 무작위 표시), `ScoreInput`, `RestoreCard`, `SessionCheck`, `HistoryList`, `QrHandoff`(P1).
- **도메인** `src/lib/sens/`: `math.ts`, `bisect.ts`, `presets.ts`, `interp.ts`, `storage.ts`, `schema.ts`(JSON 불러오기 검증), `constants.ts`, `iniParser.ts`(P2), `dpiMeter.ts`(P1).
- **저장**: 폰 localStorage. 단일 키 `sens:state`에 `{ version: 1, ... }` 하나로 버전 관리(키에 버전 넣지 않음). 내보내기 = JSON 다운로드/클립보드, 불러오기 = 파일 또는 붙여넣기, `schema.ts`로 범위 검증(슬라이더 1~100, 수직 배율 범위는 Phase 0 확인값, DPI 100~6400).
- **URL/QR 이동**: 상태를 `lz-string` 류로 압축해 URL 해시에 넣음. QR은 클라이언트 생성. 서버 없음.
- **테스트**: vitest만. `bisect.ts`(전이표 전 행 + 클램프 + undo), `math.ts`(ratio/Δ 왕복, D-2), `interp.ts`(경계·15x), `schema.ts`. E2E 없음(개인용).
- **폰 사용성**: 큰 버튼, 타이머 소리(첫 탭 오디오 언락), Screen Wake Lock(최신 iOS 지원, 구형은 안내).

## 8. 검증 계획

### Phase 0 — 실측 스파이크 (구현 전, PC방 1~2회 방문)
**구현 게이트(통과 전 Step 3 지표 설계 확정 금지):**
- [ ] **명중 수 측정 수단**: 훈련장에서 (a) 명중 표시/카운트 UI가 있는지, (b) 정지 표적 탄흔을 스크린샷으로 셀 수 있는지, (c) 인스턴트 리플레이(ShadowPlay/Xbox Game Bar)가 PC방 PC에서 쓸 수 있는지 확인. 하나라도 가능하면 M-2 활성(P1). 전부 불가면 트래킹 지표 삭제, 플릭만.
- [ ] **플릭 지표 실행성**: M-1 정의대로 10회 왕복을 혼자 세면서 할 수 있는지, 두 표적 간격 메모.

**설정·상수:**
- [ ] 감도 메뉴 전체 캡처: 항목 이름·순서·범위·단위(정수?), 수직 배율 단위, 통일 토글 존재 여부와 동작, 가변 배율 적용 규칙. → §1-1 확정, 복원 카드 순서 확정.
- [ ] ini 필드 목록, 슬라이더 ↔ `LastConverted` 대응표(0~100, 5단위). PC방 관리 프로그램이 ini를 되돌리는지 확인.
- [ ] cm/360 실측: 일반 20/35/50/65/80 (자·테이프 방식. AHK 설치 가능하면 카운트 방식 병행) → 지수형 형태 검증.
- [ ] 내장 스케일링 역산: 일반 50 / 조준경 50 / 4x 50의 cm/360 → 프리셋 B 활성 여부.
- [ ] 1인칭 FOV 80/90/103에서 일반 50의 cm/360.
- [ ] 로비에서 캐릭터 회전으로 0-B 1바퀴 테스트가 가능한지(훈련장 입장 없이).
- [ ] 손잡이 현황(종류만. 효과 수치는 기록하지 않음).

### 자가 테스트
- 퀵 모드 1회 완주 → §6-H 시간 교정.
- 풀 모드를 2~3회 방문에 나눠 완주 → 분할 재개 흐름 검증.
- 다른 자리/다른 마우스에서 0-B 점검 + D-2 환산 1회 → "오늘용 값"으로 체감이 유지되는지.
- 7일 잠금 후 재평가 1회.
