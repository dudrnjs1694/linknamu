## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **단계별 체크리스트 위저드**로 묶어,
내가 PC방 훈련장에서 정해진 플릭 테스트를 하고 점수를 폰에 입력하면
**일반 감도 → 조준/조준경/배율 → 수직 배율** 순으로 감도를 수렴시키고,
다음 방문 때 **복원 카드로 설정을 다시 넣고 1바퀴 검증**까지 끝낼 수 있게 해 주는 개인용 웹 도구.

원칙: 계산은 보조 수단. 공식은 전부 "추정"으로 취급하고 최종 판단은 인게임 테스트로 한다. 숫자는 숨기지 않는다(내가 직접 입력하므로 블라인드는 불가능).

## 2. 리서치 정리 (요약. 출처 §12)

### 2-1. 공통 전제
DPI 고정(이 문서: 800) · 마우스 가속 OFF · 포인터 속도 6/11 · 한 번에 하나만 작은 폭으로 · 최소 `LOCK_DAYS` 유지 · 기준은 cm/360.

### 2-2. 찾는 순서
인벤(좌우 → 수직 → 좌우 섬세)은 통일 전제. 수직 체감은 "배율 감도 × 수직 배율"이므로 **일반 → 조준/조준경/배율 → 수직**.

### 2-3. 일반 감도 테스트
- 플릭 왕복(영어권) → **P0 핵심 지표**(§6-C M-1)
- 트래킹 명중 수(영어권·보텍스) → P1, §8 게이트 통과 후
- 이분법(PSA) → 챔피언–도전자 탐색으로 채택, §6-B
- 중앙 집탄(인벤) → 참고(가중치 0). 좌우 반동은 확률적
- 차량 사격장(보텍스) → 선택

### 2-4. 수직 배율 테스트
- 상탄이면 +, 하탄이면 −(인벤). 각 값에서 **첫 `V_SHOTS`발만** 판정
- 앵글 손잡이 방식(보텍스)은 **삭제된 부착물이라 불가**(사용자 확인. 패치노트 출처는 Phase 0에서 §12에 추가) → 항상 내 실제 무기 세팅, 세로 분포만 판정
- 시작값 `V0`(프로 다수 1.0). 유지가 기본, 벗어날 근거가 있는지만 확인

### 2-5. 조준·조준경
- 조준 상태 플릭(P0) / 트래킹(P1)
- 통일 vs 분리(인벤) → 프리셋 A/B(§6-E). 추천 없음
- 30초 조준 유지(clip.dor.gg) → 삭제(흔들림은 무기 애니메이션)
- "MDH 100% 내장 스케일링"(포럼 1건) → 미검증, Phase 0 역산 후 프리셋 B

### 2-6. 참고 수치
cm/360 권장 범위가 출처마다 다르고 변환 상수가 미확정 → 시작값 계산에 쓰지 않음.

### 2-7. 감도 수학 (전부 추정)
- cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각). 폴링은 영향 없음.
- 슬라이더는 지수형 추정: `LastConverted = 0.002 × 10^(슬라이더/50)` → **+50 = ×10, +1 ≈ ×1.047** `{추정, 포럼 #8889}`. `LastConverted`가 회전각(°/count)이라는 근거는 없음(따라서 이 문서는 슬라이더 → cm 절대값을 어디서도 계산하지 않는다). 조준경 50 → 0.00429 `{추정, 포럼 #607}`.
- 1인칭 FOV 영향(힙파이어 회전량이 FOV에 따라 바뀐다는 보고), 슬라이더 정수/소수 단위, 수직 입력 단위 → Phase 0.
- 형태 가정만 상대 변환(§6-D)에 사용. 절대값은 Step 3 실측(D)에서만.
- ini: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의

### 3-1. 해결하려는 것
어디까지 했는지 잊음 → 기록 / 감으로 끝없이 바꿈 → 정해진 테스트 수 안에 결정 + `LOCK_DAYS` 잠금 / 배율 재계산 → 프리셋 / PC방에서 설정 유실 → 복원 카드 + 0-B / 자리별 마우스 → 800 확인 + 1바퀴 검증.

### 3-2. 범위 (v1)
포함: 일반·조준·조준경·배율 6종·수직 배율, 프리셋 A, 체크리스트·타이머, 탐색(§6-B), D 측정, 복원 카드, 세션 점검, JSON 내보내기/불러오기, 히스토리.
제외: 공유, 서버, 프로 DB, 타 게임 변환, 모바일, 자동 측정, 푸시 알림.

### 3-3. 모드 (회차·시간은 §6-G, §6-H만 참조)
- **퀵(기본, Phase 1)**: 0-A → 0-B → 1 → 2(`T_QUICK`회, 10점 세트, 교차 없음) → 3 D 측정 → 4 프리셋 → 6

## 4. 사용자 흐름

```
매 방문: [0-B 세션 점검] → 플레이
처음: [0-A] → [0-B] → [1 시작점] → [2 일반 탐색] → [3 D 측정] → [4 조준경] → [5 수직] → [6 복원 카드 + JSON + 잠금]
```
각 단계: ① 인게임에 넣을 값 → ② 훈련장에서 할 일(타이머) → ③ 점수 입력 → ④ 다음 값.

### Step 0-A. 준비 (처음 1회)
- 주 시점(3인칭/1인칭/둘 다), 1인칭 FOV. **D 측정·0-B 검증용 시점**은 기본 3인칭(1인칭을 고르면 FOV 함께 기록)
- 현재 감도 전부(모르면 비움)
- 실제 무기 세팅(예: M416 + 보정기 + 수직 손잡이 + 4배율) — Step 5용
- **훈련장 테스트 위치 메모**(처음 한 번): 일반용 플릭 표적 쌍(거리·간격), 조준경용·4x용·8x용 표적 쌍, 360°/180° 기준 지형물, 수직 표적(`V_DIST`)
- 준비물: 테이프, 자
마우스 입력 없음(800/1000 고정 전제).

### Step 0-B. 세션 시작 점검 (매 방문, `T_CHECK`)
순서 고정:
1. Windows: 포인터 속도 6/11, "포인터 정확도 향상" OFF. (잠겨 있으면 기록하고 진행)
2. 마우스: DPI 800 · 폴링 1000Hz 확인(내 마우스면 체크만, PC방 마우스면 버튼/LED/소프트웨어). **DPI 버튼 조정이 항상 1순위**.
3. 훈련장 입장. 복원 카드 순서대로 **전체 입력** → 체크. 시점·FOV를 복원 카드 값으로 맞춤.
4. **1바퀴 검증**(D가 있을 때만): 복원 카드의 일반값 `G`·같은 시점에서 Step 3 절차를 **1회 끌기**로 수행 → `D′`. `|50·log10(D′/D)| ≤ TOL_SLIDER`면 통과. 불통과면 1회 더 끌어 **둘 다** 불통과일 때만 실패.
5. 실패 → 2번 재확인(800이 아닐 가능성이 가장 큼) → 재측정. 마우스를 800으로 바꿀 수 없으면 예비 환산(§6-D D-2, P3) 후 복원 카드 재입력.
설계상 잡는 결함: DPI 800↔1000(Δ4.8) 이상. DPI 900(Δ2.6) 같은 작은 차이는 **확실히 잡지 못한다**(약 절반만 검출됨, 명시).

### Step 1. 시작점 (자동)
`S = 현재 일반 감도 ?? 50`.

### Step 2. 일반 감도 탐색 (핵심)
규칙은 §6-B·§6-C만 참조. 흐름:
1. **init**: `S`를 먼저 테스트해 **챔피언**으로 둔다(현재 감도가 가장 좋은 사전정보). 그다음 `S ± W0` 두 끝값을 테스트하고, 점수가 높은 끝값을 챔피언과 비교한다. 끝값이 **강승**이고 확장 여지가 있으면 그 방향으로 구간을 확장(SHIFT)한다.
2. **탐색**: 매 회차 도전자 1개(챔피언 양쪽 중 긴 구간의 중점)를 테스트해 챔피언과 비교. 승패에 따라 구간이 줄거나 챔피언이 바뀐다. **끝값 챔피언이 중점 도전자를 이기면** 그 방향으로 SHIFT(확장 규칙).
3. **종료**: 구간 폭 ≤ `W_END`, 동률 `TIE_MAX`회, 또는 테스트 수 `T_MAX`. **결과 `G` = 챔피언.** 풀 모드는 종료 직전 **확인 라운드**(§6-C).
4. `undo`는 다단계(스냅샷 스택). 매 입력마다 폰에 저장.

### Step 3. D 측정 (퀵 포함, P0)
**D의 정의(문서 유일)**: 복원 카드의 일반값 `G`, 복원 카드의 시점(기본 3인칭)·FOV에서, 정면 기준 지형물이 **한 바퀴 돌아 다시 정면에 올 때까지**(360°) 마우스를 직선으로 끌었을 때 테이프 두 점 사이 거리(cm). 패드가 짧으면 180° 지형물 쌍으로 재고 ×2.
절차: 테이프 1 → 직선으로 천천히 끌기 → 같은 지형물 정면에서 멈춤 → 테이프 2 → 자로 측정. `N_MEASURE`회, 평균과 편차 기록.
결과: `D`, `G`, 시점·FOV, 각도(360/180). 0-B 검증과 cm/360 표시(§6-D D-3)의 기준. **`G`·시점·FOV가 바뀌면 D를 다시 잰다**(앱이 경고).
Phase 0의 AHK 카운트 측정은 "지수형 형태 검증", Step 3은 "내 환경 절대값"으로 역할이 다르다.

### Step 4. 조준·조준경·배율
1. 모드: **통일**(토글 ON, 조준·조준경 = 일반) / **분리**(토글 OFF, 프리셋 A / 프리셋 B(Phase 0 후) / 직접). 추천 없음.
2. 퀵: 프리셋 값을 그대로 결과에.
3. 풀 테스트(조준경 → 4x → 8x, 최대 줌 고정, 배율별 표적 쌍):
   - 후보 3개: 현재 `c`, `c − A_STEP`, `c + A_STEP`. 각 1회 테스트. §6-C M-3(20점)으로 **현재 대비 win 이상**인 후보만 채택(둘 다면 큰 차). tie면 현재 유지.
   - 채택되면(채택 후보는 정의상 끝값) 같은 방향으로 1회 더(`c ± 2·A_STEP`) 테스트해 **채택 후보 대비 win 이상**이면 교체. 최대 1회.
   - 통일 모드에서 특정 배율을 바꾸면 **분리 모드 자동 전환** + 토글 OFF 안내.
4. 테스트하지 않은 배율은 §6-F 보간. 프리셋 그대로 쓸 때는 보간 비활성.
5. 확정 후 Step 5. 이후 4x를 바꾸면 Step 5 재측정 경고.

### Step 5. 수직 배율
안내: "수직 배율은 모든 조준 모드에 공통 적용되는 것으로 **추정**(Phase 0 확인 후 문구 확정). `V0` 유지가 기본값이고 이 단계는 벗어날 근거가 있는지만 확인한다. 벗어나면 비조준 대각 이동도 왜곡된다."
1. 시작 `V0`. Step 0-A 실제 무기 세팅, 4배율(Step 4 확정값), 거리 `V_DIST`, 서서 사격.
2. 후보 값에서 **첫 `V_SHOTS`발만** 판정: "상탄 / 하탄 / 모임"(세로 분포만).
3. 상탄 → +`V_STEP`, 하탄 → −`V_STEP`. 방향이 뒤집히면 두 값의 중간(입력 단위 반올림)으로 종료. 최대 `V_MAX`회. (적응형 절차, 순서 무작위 없음)
4. 결과 + 측정 조건(배율, 그 배율 감도, 무기 세팅, 거리).

### Step 6. 복원 카드 + 내보내기 + 잠금
- **복원 카드**: 인게임 메뉴 순서(Phase 0 캡처), 각 줄 체크박스, 큰 글씨. 예비 환산이 있으면 "오늘용 값" 열 병기.
- 측정 조건: DPI 800·폴링 1000(고정), `D`·`G`·시점·FOV·각도, 무기 세팅, 게임 버전(직접 입력), 날짜.
- **JSON 내보내기 필수 단계**(클립보드 또는 파일). iOS면 "홈 화면에 추가" 안내(§7).
- 잠금 `LOCK_DAYS`. 만료 후 **재평가** → Step 2를 재평가 파라미터(§6-B: `champ = G`, `W0 → W_RE`, `SHIFT_MAX = 0`, `T_MAX = T_RE`, **동률이면 G 유지**)로 실행, 이전 점수 재사용 없음. `G`가 바뀌면 Step 3 재측정.
- 히스토리: 날짜별 복원 카드 비교. 선택: 차량 사격장 메모.

## 6. 상수·규칙 단일 정의 (본문은 이름으로만 참조)

### 6-A. 상수 저장 형식
`src/lib/sens/constants.ts`: 모든 값 `{ value, status: '추정'|'실측'|'설정', source?, measuredAt? }`.

### 6-B. 일반 감도 탐색 전이표 (정수 슬라이더 공간, 챔피언–도전자 방식)

**입력**: `S`, `W0`, `W_END`(≥ 2, 생성자에서 검증), `SHIFT_MAX`, `TIE_MAX`, `T_MAX`(모드별: `T_QUICK` / `T_FULL` / `T_RE`), `MAXSCORE`(10 또는 20), `KEEP_ON_TIE`(재평가 true, 그 외 false), `rng`(결정적 주입).
**상태**: `{ lo, hi, champ, shiftDir: -1|0|1, shifts, tieCount, tests, scores: Record<slider, Score>, history: Snapshot[], done }`.
**보조 정의**:
- `clamp`: 1~100. `round`: .5 올림. `w = hi − lo`. `dir(x)`: `x > champ`면 +1, 아니면 −1.
- 비교 결과(§6-C M-3): `win(x) | strong(x) | win(champ) | strong(champ) | tie`.
- `canShift(d)` ≡ `shifts < SHIFT_MAX` ∧ `shiftDir ∈ {0, d}` ∧ (`d > 0` ? `clamp(hi + 2·W0) > hi` : `clamp(lo − 2·W0) < lo`).
- **`SHIFT(d)`** 절차: `d > 0`: `lo = round((lo + hi)/2)`, `hi = clamp(hi + 2·W0)`, `x = hi` / `d < 0`: `hi = round((lo + hi)/2)`, `lo = clamp(lo − 2·W0)`, `x = lo`. 그다음 `shiftDir = d`, `shifts += 1`, `TEST(x)`(재사용 규칙 동일). 이어서 **비교** 행으로.
- `TEST(v)`: `scores[v]`가 있으면 재사용(테스트 수 증가 없음), 없으면 측정 후 `tests += 1`.
- 행은 위에서부터 **첫 일치 행** 적용. 모든 비교는 **`champ` vs 새로 점수가 생긴 점 `x`**.

| 시점 | 조건 | 다음 상태 |
|---|---|---|
| init | — | `lo = clamp(S − W0)`, `hi = clamp(S + W0)`. `champ = S`, `TEST(S)`. `lo == hi`면 done. 끝값 두 개를 `TEST`(순서 `rng`). `x = 점수가 높은 끝값`(같으면 `rng`). → **비교** 행. 비교 결과가 `win/strong(champ)`이면 나머지 끝값은 자동으로 챔피언에게 패한 것이므(점수가 더 낮음) 추가 처리 없음. 그 외 결과에서는 나머지 끝값이 구간 밖으로 탈락한다 |
| 비교 | `strong(x)` ∧ `x ∈ {lo, hi}` ∧ `canShift(dir(x))` | `champ = x`, `SHIFT(dir(x))` |
| 비교 | `win/strong(x)` | `x > champ`면 `lo = champ`, 아니면 `hi = champ`. `champ = x` |
| 비교 | `win/strong(champ)` ∧ `champ ∈ {lo, hi}` ∧ `x ∉ {lo, hi}` ∧ `canShift(champ == hi ? +1 : −1)` | **확장 규칙**: 먼저 보통 처리(`x > champ`면 `hi = x`, 아니면 `lo = x`), 그다음 `SHIFT(champ == hi ? +1 : −1)` |
| 비교 | `win/strong(champ)` | `x > champ`면 `hi = x`, 아니면 `lo = x` |
| 비교 | `tie` | `lo = min(champ, x)`, `hi = max(champ, x)`. `KEEP_ON_TIE`면 `champ` 유지, 아니면 `champ = 원점수 높은 쪽`(같으면 기존). `tieCount += 1` |
| 회차 시작 | `w ≤ W_END` ∨ `tests ≥ T_MAX` ∨ `tieCount ≥ TIE_MAX` | done. **결과 = champ** (풀 모드는 §6-C 확인 라운드 후) |
| 회차 시작 | 계속 | `x` = `[lo, champ]`와 `[champ, hi]` 중 **더 긴 구간의 중점**(`round`; 같으면 `rng`). `TEST(x)` → **비교** 행 |
| any | `undo` | 스냅샷 스택 pop(다단계) |

**성질**: 종료는 보장된다. init·SHIFT 테스트도 `tests`에 포함되지만 `T_MAX` 검사는 회차 시작에서만 하므로 **총 테스트 ≤ `T_MAX + SHIFT_MAX`**(퀵 최대 8회, 풀 최대 14회, 재평가 4회). 챔피언이 끝값인 회차에서 `win(x)`는 구간을 줄이지 않는다(챔피언이 내부로 들어온다). 내부 챔피언에서 `win(champ)`는 반올림 제외 ≥ 1/4, `tie`는 ≥ 1/2 줄인다. `win(x)`의 축소 비율은 챔피언이 편심된 상태(확장 SHIFT 직후)에서는 보장이 없다(예시 5 r2: 23 → 20). 정수 반올림으로 5→4, 10→8 같은 20% 축소가 생길 수 있다. 한 번 이동한 방향의 반대로는 이동하지 않는다. SHIFT가 이전에 탈락한 점을 다시 구간에 넣을 수 있으므로 `TEST`의 점수 재사용은 **실제로 발생한다**(예시 5). 확장 규칙은 노이즈만으로도 약 40% 발동하지만(시뮬레이션) 정확도에 해가 없고 비용은 평균 +0.4회다. `S`가 1 또는 100이면 init이 2회 테스트로 퇴화한다(구현에서 `S`를 2~99로 clamp하거나 경계 케이스로 고정). 세 init 점수가 모두 바닥(≤ 1)이면 정보가 없으므로 UI가 「`W0`를 늘리거나 방향을 직접 선택」하도록 안내한다.

**vitest 예시** (`MAXSCORE = 10` 임계 §6-C: tie ≤1 / win 2~4 / strong ≥5. `W0 = 10, W_END = 4, SHIFT_MAX = 2, TIE_MAX = 3, KEEP_ON_TIE = false`. `rng`: 끝값 순서 lo 먼저, 동점 끝값은 hi, 구간 길이 동률은 상위 구간.)

1. **기본 (S 유지에 가까운 수렴)** `S = 50, T_MAX = 6`: `50→7`(tests 1), `40→5, 60→8`(tests 3). x = 60: 8 vs 7 차 1 = tie → [50,60], champ 60(8 > 7), tieCount 1. 40 탈락.
   r1: champ 60 = hi. 긴 구간 [50,60] 중점 55 → `55→6`(tests 4): 6 vs 8 차 2 = win(champ). champ ∈ 끝값, x 내부, canShift(+)(shifts 0, dir 0, clamp(80) > 60) → **확장**: lo = 55 → [55,60], SHIFT(+): lo = `round(57.5) = 58`, hi = 80, x = 80, `80→4`(tests 5), shifts 1, dir +1. 비교 60(8) vs 80(4): 차 4 = win(champ); champ 60은 끝값이 아님(구간 [58,80]) → 보통 처리: x > champ → hi = 80(불변).
   r2: w 22. [58,60] 2 vs [60,80] 20 → 70 → `70→6`(tests 6): 차 2 = win(champ), champ 내부 → hi = 70 → [58,70].
   r3 시작: tests 6 ≥ T_MAX → **done, 결과 60**.
2. **확장 → 동률 챔피언 교체 → 반대 이동 금지** `S = 50, T_MAX = 12`: `50→4`, `40→3, 60→8`(tests 3). x = 60: 8 vs 4 차 4 = win(x)(strong 아님) → lo = 50, champ = 60 → [50,60]. 40 탈락.
   r1: champ 60 = hi. [50,60] 중점 55 → `55→6`(tests 4): 차 2 = win(champ), canShift(+) → 확장: lo = 55, SHIFT(+): lo = 58, hi = 80, `80→9`(tests 5), shifts 1, dir +1. 비교 60(8) vs 80(9): 차 1 = tie → [60,80], champ = 80(9 > 8), tieCount 1.
   r2: champ 80 = hi. [60,80] 중점 70 → `70→10`(tests 6): 차 1 = tie → [70,80], champ = 70(10 > 9), tieCount 2.
   r3: champ 70 = lo. [70,80] 중점 75 → `75→7`(tests 7): 차 3 = win(champ). champ 끝값(lo), x 내부, canShift(−)? shiftDir = +1 → 거짓 → 보통 처리: hi = 75 → [70,75].
   r4: w 5. [70,75] 중점 `round(72.5) = 73` → `73→8`(tests 8): 차 2 = win(champ), canShift(−) 거짓 → hi = 73 → [70,73].
   r5 시작: w 3 ≤ 4 → **done, 결과 70**.
3. **init 강승 SHIFT + 확장 SHIFT = 2회(SHIFT_MAX 도달)** `S = 50, T_MAX = 12`: `50→2`, `40→1, 60→8`(tests 3). x = 60: 차 6 = strong(x), 끝값, canShift(+) → champ = 60, SHIFT(+): lo = `round(50) = 50`, hi = 80, `80→10`(tests 4), shifts 1, dir +1. 비교 60(8) vs 80(10): 차 2 = win(x) → lo = 60, champ = 80 → [60,80].
   r1: champ 80 = hi. [60,80] 중점 70 → `70→6`(tests 5): 차 4 = win(champ), canShift(+)(shifts 1 < 2, dir +1, clamp(100) > 80) → 확장: lo = 70 → [70,80], SHIFT(+): lo = 75, hi = 100, `100→5`(tests 6), shifts 2. 비교 80(10) vs 100(5): 차 5 = strong(champ); champ 80은 내부([75,100]) → 보통 처리: hi = 100(불변).
   r2: [75,80] 5 vs [80,100] 20 → 90 → `90→7`(tests 7): 차 3 = win(champ) → hi = 90 → [75,90].
   r3: [75,80] 5 vs [80,90] 10 → 85 → `85→8`(tests 8): 차 2 = win(champ) → hi = 85 → [75,85].
   r4: [75,80] 5 = [80,85] 5 → rng 상위 → `round(82.5) = 83` → `83→9`(tests 9): 차 1 = tie → [80,83], champ 80(10 > 9), tieCount 1.
   r5 시작: w 3 → **done, 결과 80**. (shifts = 2이므로 이후 어떤 strong도 SHIFT하지 않음)
4. **클램프 = 이동 불가** `S = 95, T_MAX = 6`: lo 85, hi 100. `95→3`, `85→1, 100→9`(tests 3). x = 100: 차 6 = strong(x), 끝값이지만 `clamp(120) = 100`, 100 > 100 거짓 → canShift 거짓 → 다음 행 `win/strong(x)`: lo = 95, champ = 100 → [95,100].
   r1: champ 100 = hi. [95,100] 중점 `round(97.5) = 98` → `98→9`(tests 4): 차 0 = tie → [98,100], champ = 100(같으면 기존), tieCount 1.
   r2 시작: w 2 ≤ 4 → **done, 결과 100**.
5. **S 유지, 하향 확장, 점수 재사용** `S = 50, T_MAX = 6`: `50→7`, `40→6, 60→6`(tests 3). x: 동점 → rng → 60. 6 vs 7 차 1 = tie → [50,60], champ 50(7 > 6), tieCount 1. 40 탈락.
   r1: champ 50 = lo. [50,60] 중점 55 → `55→5`(tests 4): 차 2 = win(champ), canShift(−)(shifts 0, dir 0, clamp(30) < 50) → 확장: hi = 55 → [50,55], SHIFT(−): hi = `round(52.5) = 53`, lo = 30, `30→3`(tests 5), shifts 1, dir −1. 비교 50(7) vs 30(3): 차 4 = win(champ); champ 50 내부([30,53]) → 보통 처리: lo = 30(불변).
   r2: [30,50] 20 vs [50,53] 3 → 40 → **`TEST(40)` 재사용**(점수 6, tests 5 유지): 6 vs 7 차 1 = tie → [40,50], champ 50, tieCount 2.
   r3: champ 50 = hi. [40,50] 중점 45 → `45→6`(tests 6): 차 1 = tie → [45,50], champ 50, tieCount 3.
   r4 시작: tieCount 3 ≥ TIE_MAX(tests 6 = T_MAX, w 5) → **done, 결과 50**. (S 유지)
6. **재평가** `S = G = 50, W0 = W_RE = 5, SHIFT_MAX = 0, T_MAX = T_RE = 4, KEEP_ON_TIE = true`: `50→7`, `45→6, 55→8`(tests 3). x = 55: 차 1 = tie → [50,55], **champ 50 유지**(KEEP_ON_TIE), tieCount 1.
   r1: champ 50 = lo. [50,55] 중점 `round(52.5) = 53` → `53→7`(tests 4): 차 0 = tie → [50,53], champ 50, tieCount 2.
   r2 시작: tests 4 ≥ T_MAX → **done, 결과 50 = G**. D 재측정 없음.

### 6-C. 지표와 비교 규칙
- **M-1 플릭 점수(P0)**: 두 표적 사이를 플릭하고 **보정 없이 즉시 1발** 사격 → 명중이면 1점. 1테스트 = `FLICK_N`회 × `SETS`세트(퀵 5×2 = 10점, 풀 10×2 = 20점). 세트가 끝날 때마다 폰에 입력.
- **교차 세트**: **퀵은 교차 없음**(후보별 2세트 연속). **풀은 init의 세 후보(S, lo, hi)만 교차**(A B C A B C, 설정 변경 왕복 +3회, §6-H 반영). 탐색 회차는 도전자만 연속 2세트, 챔피언 점수 재사용.
- **확인 라운드(풀 모드)**: `done` 직전 최종 챔피언과 **마지막 비교에서 챔피언이 아니었던 쪽**(tie 포함) 각 1회 재측정(`CONFIRM = 2`, `T_MAX` 밖 별도). 두 점은 기존 점수 + 재측정 점수 합산(40점 만점, 임계는 20점 표 × 2)으로 최종 비교 → 승자가 결과, **tie면 챔피언 유지**. 결과만 바뀌고 구간 상태는 바꾸지 않는다. 목적은 오래된 챔피언 점수의 피로·학습 드리프트 보정이며, 정상성 모델에서는 효과가 거의 0이므로 **존치 여부는 Phase 0의 플릭 점수 드리프트 측정(§8)으로 결정**한다.
- **M-2 트래킹 점수(P1)**: 이동 표적 `TRACK_SEC`초 명중 수. `MAXSCORE_TRACK`은 Phase 0에서 정한 기준 탄수(그 값에 가까운 10/20점 임계표 사용).
- **M-3 비교(정수 절대값)**:

| `MAXSCORE` | tie | win | strong |
|---|---|---|---|
| 10 | 차 ≤ 1 | 차 2~4 | 차 ≥ 5 |
| 20 | 차 ≤ 2 | 차 3~6 | 차 ≥ 7 |

- 지표 2개(P1 이후) 합성: 같은 방향 win+win → win, win+strong → strong, strong+strong → strong; tie+win → win, tie+strong → win; tie+tie → tie; 방향 반대 → tie.
- **M-4 집탄**: 기록만, 가중치 0.
- **노이즈 참고**(정확 계산, 동일 성능 p = 0.6): 점수 차의 표준편차 10점 2.19 / 20점 3.10. 판정 확률 10점 tie 51% / win 46% / strong 4%, 20점 58% / 39% / 3.5%. **구간 폭은 정밀도 지표가 아니다**(폭이 2~3으로 끝나도 결과가 최적점에서 ±10 벗어날 확률이 모델상 5~25%). UI 문구: "퀵 모드는 거친 탐색입니다. 결과는 1주 사용 후 재평가로 다듬습니다." 최종 폭 분포 수치는 Phase 1에서 §6-B 구현 시뮬레이션으로 갱신.

### 6-D. 변환
- **D-1 형태 가정**: `ratio(Δ) = 10^(Δ/50)`, `Δslider(m) = 50·log10(m)` `{추정}`
- **D-2 예비 환산(P3)**: 800으로 설정할 수 없는 마우스에서만. 거리 기준 `Δslider = 50·log10(D′/D)`(D′ > D = 덜 돌았다 → 올림). DPI 기준 `Δslider = 50·log10(800 / DPI_오늘)`(DPI ↑ → 내림). 모든 항목에 같은 Δ, 정수 반올림, "오늘용" 표시, 원본 유지.
- **D-3 절대값 표시**: `cm360(X) = D / ratio(X − G)`(X ↑ → cm/360 ↓). D-1 의존이므로 "추정" 표기, 편차 병기.

| 항목 | A 커뮤니티형 (일반 대비 슬라이더 Δ) | B 0% 초점거리형 |

A의 Δ가 슬라이더 차이인지는 출처(인벤 분리파) 재확인 항목. 3x = −4는 이 문서의 결정. 프리셋 적용 시 보간(§6-F) 비활성.

### 6-F. 보간
축 `log10(배율)`, 조준경 = 1x. 테스트한 점 사이는 슬라이더 선형 보간 후 정수 반올림. 15x = 8x와 같은 슬라이더 값. 테스트하지 않은 끝은 가장 가까운 테스트 점 값.

- 다른 자리(PC방 마우스 800 설정)에서 0-B → 1바퀴 검증 통과 여부(2회 규칙).
- `LOCK_DAYS` 후 재평가 1회(iOS면 스토리지 유지 여부 확인).

## 9. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 감도 공식 미검증 | 절대값은 실측에서만. 형태 가정은 상대 변환에만. 불일치 시 보간표 교체(§8) |
| 설정 항목·통일 토글이 가정과 다름 | 게이트 B 1순위. 부재 시 분기 명시 |
| PC방에서 설정이 실제로는 보존됨 | 게이트 A. 보존되면 복원 카드는 백업 |
| 명중 피드백/명중 수를 셀 수 없음 | 게이트 A 분기 |
| 체감·노이즈 편향 | 객관 지표, 순서 무작위, S를 챔피언으로(하향 편향 제거), 정수 임계, 결과 = 챔피언, 동률은 원점수 우선(재평가는 G 유지), 풀 모드 확인 라운드, "폭 ≠ 정밀도" 안내 |
| 초기 추정 크게 틀림 | init 강승 SHIFT + 확장 규칙(한 방향, 최대 `SHIFT_MAX`회) |
| 수직 결과 무효화 | 순서(배율 → 수직) + 4x 변경 시 경고 |
| 자리별 마우스 / DPI 바뀜 | 0-B 800·1000 확인 + 같은 감도·시점 1바퀴 검증(`TOL_SLIDER`, 2회 규칙) |
| `G`·시점·FOV 변경 후 D 불일치 | Step 3 재측정 경고 |
| 폰 스토리지 삭제(iOS) | JSON 내보내기 필수, 홈 화면 추가, 복구 진입점 |
| 시간 과금·세션 제한 | 퀵 기본, `SESSION_LIMIT` 블록, 자동 저장 |
| 폰 화면 꺼짐 / 소리 | Wake Lock, 첫 탭 오디오 언락 |
