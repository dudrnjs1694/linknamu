# 배틀그라운드 감도 찾기 프로그램 기획서 (v0.4)

> 작성일: 2026-10-18 (v0.1 → v0.2 → v0.3 → v0.3.1 → v0.4)
> 상태: 기획 초안 (구현 전). **Phase 0 실측 착수 가능 상태를 목표로 한 버전**
> 대상: PC 배틀그라운드(PUBG: BATTLEGROUNDS) 마우스 유저. **개인용(사용자 1명), PC방, DPI 800 · 폴링 1000Hz 고정**

## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **단계별 체크리스트 위저드**로 묶어,
내가 PC방 훈련장에서 정해진 플릭 테스트를 하고 점수를 폰에 입력하면
**일반 감도 → 조준/조준경/배율 → 수직 배율** 순으로 감도를 수렴시키고,
다음 방문 때 **복원 카드로 설정을 다시 넣고 1바퀴 검증**까지 끝낼 수 있게 해 주는 개인용 웹 도구.

원칙: 계산은 보조 수단. 공식은 전부 "추정"으로 취급하고 최종 판단은 인게임 테스트 결과로 한다. 숫자는 숨기지 않는다(내가 직접 입력하므로 블라인드는 불가능).

## 2. 리서치 정리 (요약. 상세 출처 §12)

### 2-1. 공통 전제
DPI 고정(이 문서: 800) · 마우스 가속 OFF · 포인터 속도 6/11 · 한 번에 하나만 작은 폭으로 · 최소 1주일 유지 · 기준은 cm/360.

### 2-2. 찾는 순서
인벤(좌우 → 수직 → 좌우 섬세)은 통일 전제. 수직 체감은 "배율 감도 × 수직 배율"이므로 **일반 → 조준/조준경/배율 → 수직**.

### 2-3. 일반 감도 테스트 (채택 여부)
- 플릭 왕복(영어권) → **P0 핵심 지표** (§6-C M-1)
- 트래킹 명중 수(영어권·보텍스) → **P1**, §8 게이트 통과 후
- 이분법(PSA) → 채택, §6-B 전이표
- 중앙 집탄(인벤) → 참고(가중치 0). 좌우 반동은 확률적
- 차량 사격장(보텍스) → 선택

### 2-4. 수직 배율 테스트
- 상탄이면 +, 하탄이면 −(인벤). **각 값에서 첫 10발만 판정**(적응 효과 제한)
- 앵글 손잡이 방식(보텍스)은 **삭제된 부착물이라 불가** → 항상 내 실제 무기 세팅, 세로 분포만 판정
- 시작값 1.0(프로 다수). 1.0 유지가 기본, 벗어날 근거가 있는지만 확인

### 2-5. 조준·조준경
- 조준 상태 플릭(P0) / 트래킹(P1)
- 통일 vs 분리(인벤) → 프리셋 A/B(§6-E). 추천 없음
- 30초 조준 유지(clip.dor.gg) → **삭제**(흔들림은 무기 애니메이션)
- "MDH 100% 내장 스케일링"(포럼 1건) → 미검증, Phase 0 역산 후 프리셋 B

### 2-6. 참고 수치
cm/360 권장 범위가 출처마다 다르고 변환 상수가 미확정 → **시작값 계산에 쓰지 않음.**

### 2-7. 감도 수학 (전부 추정)
- cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각). 폴링은 영향 없음.
- 슬라이더는 지수형 추정: `LastConverted = 0.002 × 10^(슬라이더/50)` → **+50 = ×10, +1 ≈ ×1.047** `{추정, 포럼 #8889}`. `LastConverted`가 회전각이라는 근거는 없음. 조준경 50 → 0.00429 `{추정, 포럼 #607}`.
- 1인칭 FOV 영향, 슬라이더 정수 단위, 수직 입력 단위 → Phase 0.
- 형태 가정만 상대 변환(§6-D)에 사용. 절대값은 Step 2 실측에서만.
- ini: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의

### 3-1. 해결하려는 것
어디까지 했는지 잊음 → 기록 / 감으로 끝없이 바꿈 → 정해진 테스트 수 안에 결정 + 7일 잠금 / 배율 재계산 → 프리셋 / PC방에서 설정 유실 → 복원 카드 + 0-B / 자리별 마우스 → 800 확인 + 1바퀴 검증.

### 3-2. 범위 (v1)
포함: 일반·조준·조준경·배율 6종·수직 배율, 프리셋 A, 체크리스트·타이머, 이분법, 복원 카드, 세션 점검, JSON 내보내기/불러오기, 히스토리.
제외: 공유, 서버, 프로 DB, 타 게임 변환, 모바일, 자동 측정, 푸시 알림.

### 3-3. 모드
회차·시간은 **§6-G, §6-H만** 참조.
- **퀵(기본, Phase 1)**: 0-A → 0-B → 1 → 3(테스트 `T_QUICK`회, **거친 탐색: ±3~5 정확도**) → 4 프리셋 → 6
- **풀**: 전 단계. `SESSION_LIMIT` 블록으로 분할, 방문 2~3회
- **세션 점검(매 방문)**: 0-B만

## 4. 사용자 흐름

```
매 방문: [0-B 세션 점검] → 플레이
처음/재평가: [0-A] → [0-B] → [1] → [2 실측(권장, PC방 마우스면 필수)] → [3 일반] → [4 조준경] → [5 수직] → [6 복원 카드 + JSON 내보내기 + 7일 잠금]
```
각 단계: ① 인게임에 넣을 값 → ② 훈련장에서 할 일(타이머) → ③ 결과 입력(점수) → ④ 다음 값.

### Step 0-A. 준비 (처음 1회)
입력:
- 주 시점(3인칭/1인칭/둘 다), 1인칭 FOV
- 현재 감도 전부(모르면 비움)
- 실제 무기 세팅(예: M416 + 보정기 + 수직 손잡이 + 4배율) — Step 5용
- **훈련장 테스트 위치 메모**(처음 한 번 정해 저장): 일반용 플릭 표적 쌍(거리·간격), 조준경용·4x용·8x용 플릭 표적 쌍(배율마다 시야가 달라 별도), 360°/180° 기준 지형물, 수직 테스트 표적(`V_DIST`)
- 준비물: 테이프, 자
마우스는 입력 없음(800/1000 고정 전제).

### Step 0-B. 세션 시작 점검 (매 방문, `T_CHECK`)
순서 고정:
1. Windows: 포인터 속도 6/11, "포인터 정확도 향상" OFF.
2. 마우스: DPI 800 · 폴링 1000Hz 확인(내 마우스면 체크만, PC방 마우스면 버튼/LED/소프트웨어로 설정). **DPI 버튼 조정이 항상 1순위**(재입력 비용이 없음).
3. 훈련장 입장(로딩 시간은 §6-H에 포함). 복원 카드 순서대로 **전체 입력** → 체크.
4. **1바퀴 검증**(Step 2를 해서 D가 있을 때만): Step 2 절차를 1회 수행해 D′ 측정. `|50·log10(D′/D)| ≤ TOL_SLIDER` 이면 통과.
5. 불통과 → 2번 재확인(800이 아닐 가능성이 가장 큼) → 재측정. 그래도 불통과이고 마우스를 800으로 바꿀 수 없으면 예비 환산(§6-D D-2, P3) 적용 후 복원 카드 재입력.
D가 없으면(Step 2 생략) 4~5번은 건너뛴다.

### Step 1. 시작점 (자동)
`S = 현재 일반 감도 ?? 50`. 다른 입력은 쓰지 않는다.

### Step 2. cm/360 실측 (권장. PC방 마우스 사용자는 필수)
**D의 정의(문서 유일)**: 일반 감도 S에서, 정면 기준 지형물이 **한 바퀴 돌아 다시 정면에 올 때까지**(360°) 마우스를 직선으로 끌었을 때 테이프 두 점 사이 거리(cm). 패드가 짧으면 180° 지형물 쌍으로 재고 ×2.
절차: 테이프 1 → 직선으로 천천히 끌기 → 같은 지형물 정면에서 멈춤 → 테이프 2 → 자로 측정. `N_MEASURE`회 반복, 평균과 편차 기록(자 눈금 ±0.5cm + 손 흔들림).
결과: `D`(= cm/360 at S), 측정 각도(360/180). 이후 cm/360 표시(§6-D D-3)와 0-B 검증의 기준. 건너뛰면 cm/360 표시와 0-B 4~5번이 꺼진다.
Phase 0의 AHK 카운트 측정은 "지수형 형태 검증", Step 2는 "내 환경 절대값"으로 역할이 다르다.

### Step 3. 일반 감도 탐색 (핵심)
규칙은 §6-B(전이표)·§6-C(지표)만 참조. 흐름:
1. **브래킷**: `lo = S−W0`, `hi = S+W0`(클램프). 두 값을 각각 테스트(순서 무작위). 한쪽이 **강승**이면 그 방향으로 `2·W0`만큼 이동해 새 끝값만 테스트(한 방향으로만, 최대 `SHIFT_MAX`회). 그 외는 승자(동률이면 §6-B 규칙)를 **챔피언**으로 두고 탐색 단계로.
2. **탐색**: 매 회차 도전자 1개를 테스트해 챔피언과 비교. 결과에 따라 구간이 **반드시** 줄어들거나 챔피언이 바뀐다(§6-B).
3. **종료**: 구간 폭 ≤ `W_END`, 동률 `TIE_MAX`회, 또는 테스트 수 `T_QUICK`/`T_FULL` 도달. **결과 = 챔피언.**
4. `undo`로 직전 상태 복원. 진행 상태는 매 입력마다 폰에 저장.

### Step 4. 조준·조준경·배율
1. 모드: **통일**(토글 ON, 조준·조준경 = 일반) / **분리**(토글 OFF, 프리셋 A / 프리셋 B(Phase 0 후) / 직접). 추천 없음.
2. 퀵: 프리셋 값을 그대로 결과에.
3. 풀 테스트(조준경 → 4x → 8x, 최대 줌 고정, 배율별 플릭 표적 쌍 사용):
   - 후보 3개: 현재값, 현재−`A_STEP`, 현재+`A_STEP`. 각 1회 테스트(점수 재사용 없음). 최고점이 극값이면 같은 방향으로 1회 추가(최대 1회). 동률은 현재값 유지.
   - 통일 모드에서 특정 배율 값을 바꾸면 **분리 모드 자동 전환** + 토글 OFF 안내.
4. 테스트하지 않은 배율은 §6-F 보간. 프리셋을 그대로 쓸 때는 보간 비활성(프리셋 값 우선).
5. 확정 후 Step 5. 이후 4x를 바꾸면 Step 5 재측정 경고.

### Step 5. 수직 배율
안내: "수직 배율은 모든 조준 모드에 공통 적용되는 것으로 **추정**된다(Phase 0 확인 후 문구 확정). 기본 1.0 유지가 기본값이고, 이 단계는 벗어날 근거가 있는지만 확인한다. 1.0을 벗어나면 비조준 대각 이동도 왜곡된다."
1. 시작 `V0 = 1.0`. Step 0-A의 실제 무기 세팅, 4배율(Step 4 확정값), 거리 `V_DIST`, 서서 사격.
2. 후보 값에서 **첫 10발만** 판정: "상탄 / 하탄 / 모임"(세로 분포만).
3. 상탄 → +`V_STEP`, 하탄 → −`V_STEP`. 방향이 한 번 뒤집히면 두 값의 중간(입력 단위 반올림)으로 종료. 최대 `V_MAX`회. 후보 순서 무작위.
4. 결과 + 측정 조건(배율, 그 배율 감도, 무기 세팅, 거리).

### Step 6. 복원 카드 + 내보내기 + 7일 잠금
- **복원 카드**: 인게임 메뉴 순서(Phase 0 캡처 순서), 각 줄 체크박스, 큰 글씨. 예비 환산이 있으면 "오늘용 값" 열 병기.
- 측정 조건: DPI 800·폴링 1000(고정), D(cm/360), 시점, FOV, 무기 세팅, 게임 버전(직접 입력), 날짜.
- **JSON 내보내기 필수 단계**(클립보드 복사 또는 파일). iOS면 "홈 화면에 추가" 안내(§7).
- 잠금 `LOCK_DAYS`. 재방문 시 "N일 경과". 만료 후 "재평가" → Step 3 축소판: `lo=S−W_RE`, `hi=S+W_RE`, 이전 점수 재사용 없이 브래킷 2회 + 탐색 2회(총 4회).
- 히스토리: 날짜별 복원 카드 비교.
- 선택: 차량 사격장 메모.

## 6. 상수·규칙 단일 정의 (본문은 이름으로만 참조)

### 6-A. 상수 저장 형식
`src/lib/sens/constants.ts`: 모든 값 `{ value, status: '추정'|'실측'|'설정', source?, measuredAt? }`.

### 6-B. 일반 감도 탐색 전이표 (정수 슬라이더 공간, 챔피언–도전자 방식)

상태 `{ lo, hi, champ, phase: 'bracket'|'search'|'done', shiftDir: -1|0|1, shifts, tieCount, tests, scores: Record<slider, number>, history[] }`
비교 결과는 §6-C로 `win(x) | win(champ) | strong(x) | strong(champ) | tie` 중 하나. 폭 `w = hi − lo`. `clamp`는 1~100.

| phase | 상황 | 다음 상태 |
|---|---|---|
| init | — | `lo = clamp(S−W0)`, `hi = clamp(S+W0)`. 두 값 테스트(순서 무작위, tests += 2). phase = bracket. `lo == hi`면 done(champ = lo) |
| bracket | `strong(hi)` 이고 `shifts < SHIFT_MAX` 이고 `shiftDir ∈ {0, +1}` | `shiftDir = +1`, `lo = hi`, `hi = clamp(hi + 2·W0)`, 새 hi 테스트(tests += 1), `shifts += 1`. hi가 클램프로 lo와 같아지면 champ = lo, phase = search |
| bracket | `strong(lo)` 이고 `shifts < SHIFT_MAX` 이고 `shiftDir ∈ {0, −1}` | 대칭 (`shiftDir = −1`, `hi = lo`, `lo = clamp(lo − 2·W0)`) |
| bracket | `win/strong(hi)` (이동 불가 포함) | `champ = hi`, phase = search |
| bracket | `win/strong(lo)` (이동 불가 포함) | `champ = lo`, phase = search |
| bracket | `tie` | `champ = S에 더 가까운 끝값`(같으면 lo), `tieCount += 1`, phase = search |
| search | 회차 시작, `w ≤ W_END` 또는 `tests ≥ T_MAX` 또는 `tieCount ≥ TIE_MAX` | phase = done. **결과 = champ** |
| search | 회차 시작(계속) | 도전자 `x` = `[lo, champ]`와 `[champ, hi]` 중 **더 긴 구간의 중점**(`round`, 같으면 무작위). `x`에 점수가 있으면 재사용, 없으면 테스트(tests += 1) |
| search | `win/strong(x)` | `x > champ`면 `lo = champ`, 아니면 `hi = champ`. `champ = x` |
| search | `win/strong(champ)` | `x > champ`면 `hi = x`, 아니면 `lo = x` |
| search | `tie` | `lo = min(champ, x)`, `hi = max(champ, x)`, `champ = 구간 중앙에 더 가까운 쪽`(같으면 x), `tieCount += 1` |
| any | `undo` | history pop |

성질: 챔피언이 끝값인 첫 회차는 구간이 줄지 않을 수 있지만 챔피언이 내부로 들어오고, 이후 매 회차 구간이 최소 1/4 줄거나 동률로 수렴한다. 한 번 이동한 방향의 반대로는 이동하지 않는다.

**vitest 예시 (임계는 10점 기준 §6-C, S = 50, W0 = 10, W_END = 4, TIE_MAX = 2):**
1. `40→5, 60→7`: 차 2 = win(hi) → champ 60, search [40,60]. 도전자: [40,60] 중점 50 → `50→8`: 차 1 = tie → [50,60], champ = 중앙(55)에 같은 거리 → x=50, tieCount 1. 도전자: [50,60] 중점 55 → `55→6`: 차 2 = win(champ 50), x>champ → hi=55 → [50,55]. 도전자 53(`round(52.5)`) → `53→7`: 차 1 = tie → [50,53], champ 53(중앙 51.5에 더 가까움), tieCount 2 → **done, 결과 53**.
2. `40→3, 60→8`: 차 5 = strong(hi), shiftDir 0 → 이동: lo=60, hi=80, `80→5`: 60 vs 80 차 3 = win(lo) → champ 60, search [60,80]. 도전자 70 → `70→9`: win(x), x>champ → lo=60, champ=70, [60,80]. 도전자: [60,70]·[70,80] 같음 → 무작위, 예: 75 → `75→6`: win(champ), x>champ → hi=75 → [60,75]. 도전자: [60,70](10) > [70,75](5) → 65 → `65→8`: 차 1 = tie → [65,70], champ 70(중앙 67.5에 더 가까운 건 65? 65:2.5, 70:2.5 → 같으면 x=65) → champ 65, tieCount 1. `w=5 > 4` → 도전자 68(`round(67.5)`) → `68→9`: 차 1 = tie → [65,68], tieCount 2 → **done, 결과 = champ**(규칙상 68, 중앙 66.5에 더 가까움).
3. 이동 후 반대 방향 강승 금지: `40→2, 60→8` strong(hi) → lo=60, hi=80, `80→3`: 차 5 = strong(lo)이지만 `shiftDir=+1` → 이동 불가 → champ 60, search [60,80]. (원 구간 [40,60]으로 되돌아가지 않음)
4. 클램프: S=95 → lo=85, hi=100. `85→4, 100→9` strong(hi) → 이동 시 `hi = clamp(120) = 100 == lo(100)` → champ = 100, search, `w = 0 ≤ W_END` → done 100.

### 6-C. 지표와 비교 규칙
- **M-1 플릭 점수(P0)**: 두 표적 사이를 플릭하고 **보정 없이 즉시 1발** 사격 → 명중이면 1점. 1테스트 = `FLICK_N`회 × `SETS`세트(퀵 5×2 = 10점, 풀 10×2 = 20점). 세트 사이에 다른 후보 세트를 끼워 교차(A B A B).
- **M-2 트래킹 점수(P1)**: 이동 표적 `TRACK_SEC`초 사격 명중 수. 측정 수단은 §8 게이트에서 확정.
- **M-3 비교(정수 절대값)**:

| 만점 | tie | win | strong |
|---|---|---|---|
| 10 | 차 ≤ 1 | 차 2~3 | 차 ≥ 4 |
| 20 | 차 ≤ 2 | 차 3~6 | 차 ≥ 7 |

- 지표가 2개(P1 이후)면 지표별 판정 후 다수결, 1:1이면 tie. strong은 두 지표 모두 strong일 때만.
- **M-4 집탄**: 기록만, 가중치 0.
- 퀵 모드의 10점 척도는 노이즈(표준편차 약 1.5)가 커서 **거친 탐색**임을 UI에 표시한다.

### 6-D. 변환
- **D-1 형태 가정**: `ratio(Δ) = 10^(Δ/50)`, `Δslider(m) = 50·log10(m)` `{추정}`
- **D-2 예비 환산(P3)**: 800으로 설정할 수 없는 마우스에서만. 거리 기준 `Δslider = 50·log10(D′/D)`(D′ > D = 덜 돌았다 → 올림, 방향 일치). DPI 기준 `Δslider = 50·log10(800 / DPI_오늘)`(DPI ↑ → 내림). 모든 항목에 같은 Δ, 정수 반올림, "오늘용" 표시, 원본 유지.
- **D-3 절대값 표시**: D가 있을 때만 `cm360(X) = D / ratio(X − S_D)`(`S_D` = D를 잰 당시 일반 감도), 편차 병기.

### 6-E. 프리셋 (단일 정의)
| 항목 | A 커뮤니티형 (일반 대비 슬라이더 Δ) | B 0% 초점거리형 |
|---|---|---|
| 조준 | −1 | Phase 0 후 |
| 조준경(1x) | −1 | `50·log10(m_목표 / m_내장)`, `m_목표 = tan(fov_배율/2) / tan(fov_힙/2)` |
| 2x | −2 | 〃 |
| 3x ~ 15x | −4 | 〃 |
A의 Δ가 "슬라이더 차이"인지는 출처(인벤 분리파) 재확인 항목. 3x = −4는 이 문서의 결정. 프리셋 적용 시 보간(§6-F)은 비활성.

### 6-F. 보간
축 `log10(배율)`, 조준경 = 1x. 테스트한 점 사이는 슬라이더 선형 보간 후 정수 반올림. 15x = 8x와 **같은 슬라이더 값**. 테스트하지 않은 끝은 가장 가까운 테스트 점 값.

## 7. 기술 설계

- **스택**: Next.js 14 App Router, TypeScript, Tailwind. 서버 코드 없음. `vitest` 추가(현재 `package.json`에 테스트 러너 없음).

- **컴포넌트** `src/components/sens/`: `Wizard`, `StepCard`, `Checklist`, `Timer`, `CandidatePicker`(후보 순서 무작위), `ScoreInput`, `RestoreCard`, `SessionCheck`, `HistoryList`, `ExportImport`.
- **도메인** `src/lib/sens/`: `constants.ts`, `bisect.ts`(§6-B), `compare.ts`(§6-C), `math.ts`(§6-D), `presets.ts`(§6-E), `interp.ts`(§6-F), `storage.ts`, `schema.ts`.
- **저장**: 폰 localStorage 단일 키 `sens:state` = `{ version: 1, ... }`. **iOS Safari 대응**: 7일 미방문 시 스토리지가 삭제될 수 있으므로 (a) Step 6에서 JSON 내보내기를 필수 단계로, (b) "홈 화면에 추가" 안내, (c) 상태가 비어 있으면 첫 화면에 "JSON 붙여넣기로 복구" 진입점.

- **폰 사용성**: 큰 버튼, 타이머 소리(첫 탭 오디오 언락), Screen Wake Lock(미지원 시 자동 잠금 끄기 안내).

### Phase 0 — 실측 스파이크 (구현 전, PC방 1~2회 방문)

**게이트 A — 환경 사실 (결과에 따라 설계 범위가 바뀜):**
- [ ] **PC방 재로그인/자리 이동 시 PUBG 감도 설정이 보존되는지.** 어떤 항목이 초기화되는지(감도만? 키 설정도?). → 복원 카드·0-B 범위 결정
- [ ] **훈련장 1세션 시간 제한**(`SESSION_LIMIT`)과 입장·로딩 시간. → §6-H 블록 재배치
- [ ] **정지 표적 1발 명중 피드백 방식**(소리/표시/탄흔). → M-1 실행 가능성
- [ ] **이동 표적 명중 수 측정 수단**: 훈련장 카운트 UI / 탄흔 스크린샷 / 인스턴트 리플레이(PC방 PC에서 가능?) → M-2(P1) 활성 여부

**게이트 B — 설정 구조:**
- [ ] 감도 메뉴 전체 캡처: 항목 이름·순서·범위·단위(정수?), 수직 배율 단위·범위, **통일 토글 존재 여부와 동작**, 가변 배율 적용 값, 인게임 마우스 가속/스무딩 옵션 유무 → §1-1·복원 카드 순서 확정
- [ ] ini 필드 목록, 슬라이더 ↔ `LastConverted` 대응표(0~100, 5단위). PC방에서 ini가 되돌려지는지

**상수 실측:**
- [ ] 일반 20/35/50/65/80에서 cm/360(자·테이프, AHK 가능하면 병행) → 지수형 형태 검증
- [ ] 일반 50 / 조준경 50 / 4x 50의 cm/360 → 내장 스케일링 역산 → 프리셋 B
- [ ] 1인칭 FOV 80/90/103에서 일반 50의 cm/360
- [ ] 로비 캐릭터 회전으로 1바퀴 검증 대체 가능 여부(UI 드래그라 **거의 불가**로 예상)
- [ ] 훈련장 테스트 위치 확정(일반·조준경·4x·8x 플릭 표적 쌍, 360°/180° 지형물, 수직 표적) → Step 0-A 기본값

### 자가 테스트
- 퀵 모드 1회 완주 → §6-H 교정.
- 풀 모드를 `SESSION_LIMIT` 블록으로 2~3회 방문에 나눠 완주 → 분할 재개 검증.
- 다른 자리(PC방 마우스를 800으로 설정)에서 0-B → 1바퀴 검증 통과 여부.
- 7일 잠금 후 재평가 1회(iOS면 스토리지 유지 여부 확인).

## 9. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 감도 공식 미검증 | 절대값은 실측에서만. 형태 가정은 상대 변환에만. status 태그 |
| 설정 항목·통일 토글이 가정과 다름 | 게이트 B 1순위. 용어·순서는 constants에서만 참조 |
| PC방에서 설정이 실제로는 보존됨 | 게이트 A로 먼저 확인. 보존되면 복원 카드는 백업 용도로 축소 |
| 명중 피드백/명중 수를 셀 수 없음 | 게이트 A. 플릭도 불가하면 지표를 "플릭 후 표적 안 정지 여부"(주관)로 격하하고 문서에 명시 |
| 체감·노이즈 편향 | 객관 지표, 순서 무작위, 교차 세트, 정수 임계, 결과 = 챔피언(최대값 아님), 퀵은 거친 탐색 표기 |
| 초기 추정 크게 틀림 | 브래킷 이동(한 방향, 최대 2회) |
| 수직 결과 무효화 | 순서(배율 → 수직) + 4x 변경 시 경고 |
| 자리별 마우스 / DPI 바뀜 | 0-B 800·1000 확인 + 1바퀴 검증(`TOL_SLIDER`) |
| 폰 스토리지 삭제(iOS) | JSON 내보내기 필수, 홈 화면 추가, 복구 진입점 |
| 시간 과금·세션 제한 | 퀵 기본, `SESSION_LIMIT` 블록 분할, 자동 저장 |
| 폰 화면 꺼짐 / 소리 | Wake Lock, 첫 탭 오디오 언락 |
