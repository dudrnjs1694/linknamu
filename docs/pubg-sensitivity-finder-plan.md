# 배틀그라운드 감도 찾기 프로그램 기획서 (v0.5)

> 작성일: 2026-10-18 (v0.1 → … → v0.4 → v0.5)
> 상태: 기획 초안. **Phase 0(실측) 착수 가능. Phase 1(퀵 모드 구현) 착수 가능 여부는 이 버전의 리뷰로 판정**
> 대상: PC 배틀그라운드 마우스 유저. **개인용(사용자 1명), PC방, DPI 800 · 폴링 1000Hz 고정**

## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **단계별 체크리스트 위저드**로 묶어,
내가 PC방 훈련장에서 정해진 플릭 테스트를 하고 점수를 폰에 입력하면
**일반 감도 → 조준/조준경/배율 → 수직 배율** 순으로 감도를 수렴시키고,
다음 방문 때 **복원 카드로 설정을 다시 넣고 1바퀴 검증**까지 끝낼 수 있게 해 주는 개인용 웹 도구.

원칙: 계산은 보조 수단. 공식은 전부 "추정"으로 취급하고 최종 판단은 인게임 테스트로 한다. 숫자는 숨기지 않는다(내가 직접 입력하므로 블라인드는 불가능).

## 2. 리서치 정리 (요약. 출처 §12)

### 2-1. 공통 전제
DPI 고정(이 문서: 800) · 마우스 가속 OFF · 포인터 속도 6/11 · 한 번에 하나만 작은 폭으로 · 최소 `LOCK_DAYS` 유지 · 기준은 cm/360.

### 2-2. 찾는 순서
인벤(좌우 → 수직 → 좌우 섬세)은 통일 전제. 수직 체감은 "배율 감도 × 수직 배율"이므로 **일반 → 조준/조준경/배율 → 수직**.

### 2-3. 일반 감도 테스트
- 플릭 왕복(영어권) → **P0 핵심 지표**(§6-C M-1)
- 트래킹 명중 수(영어권·보텍스) → P1, §8 게이트 통과 후
- 이분법(PSA) → 채택, §6-B 전이표
- 중앙 집탄(인벤) → 참고(가중치 0). 좌우 반동은 확률적
- 차량 사격장(보텍스) → 선택

### 2-4. 수직 배율 테스트
- 상탄이면 +, 하탄이면 −(인벤). 각 값에서 **첫 `V_SHOTS`발만** 판정(적응 효과 제한)
- 앵글 손잡이 방식(보텍스)은 **삭제된 부착물이라 불가**(사용자 확인. 패치노트 출처는 Phase 0에서 §12에 추가) → 항상 내 실제 무기 세팅, 세로 분포만 판정
- 시작값 `V0`(프로 다수 1.0). 유지가 기본, 벗어날 근거가 있는지만 확인

### 2-5. 조준·조준경
- 조준 상태 플릭(P0) / 트래킹(P1)
- 통일 vs 분리(인벤) → 프리셋 A/B(§6-E). 추천 없음
- 30초 조준 유지(clip.dor.gg) → 삭제(흔들림은 무기 애니메이션)
- "MDH 100% 내장 스케일링"(포럼 1건) → 미검증, Phase 0 역산 후 프리셋 B

### 2-6. 참고 수치
cm/360 권장 범위가 출처마다 다르고 변환 상수가 미확정 → 시작값 계산에 쓰지 않음.

### 2-7. 감도 수학 (전부 추정)
- cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각). 폴링은 영향 없음.
- 슬라이더는 지수형 추정: `LastConverted = 0.002 × 10^(슬라이더/50)` → **+50 = ×10, +1 ≈ ×1.047** `{추정, 포럼 #8889}`. 회전각이라는 근거는 없음. 조준경 50 → 0.00429 `{추정, 포럼 #607}`.
- 1인칭 FOV 영향(힙파이어 회전량이 FOV에 따라 바뀐다는 보고 있음), 슬라이더 정수 단위, 수직 입력 단위 → Phase 0.
- 형태 가정만 상대 변환(§6-D)에 사용. 절대값은 Step 3 실측(D)에서만.
- ini: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의

### 3-1. 해결하려는 것
어디까지 했는지 잊음 → 기록 / 감으로 끝없이 바꿈 → 정해진 테스트 수 안에 결정 + `LOCK_DAYS` 잠금 / 배율 재계산 → 프리셋 / PC방에서 설정 유실 → 복원 카드 + 0-B / 자리별 마우스 → 800 확인 + 1바퀴 검증.

### 3-2. 범위 (v1)
포함: 일반·조준·조준경·배율 6종·수직 배율, 프리셋 A, 체크리스트·타이머, 탐색(§6-B), **D 측정**, 복원 카드, 세션 점검, JSON 내보내기/불러오기, 히스토리.
제외: 공유, 서버, 프로 DB, 타 게임 변환, 모바일, 자동 측정, 푸시 알림.

### 3-3. 모드 (회차·시간은 §6-G, §6-H만 참조)
- **퀵(기본, Phase 1)**: 0-A → 0-B → 1 → 2(테스트 `T_QUICK`회, 거친 탐색 — 최종 폭 분포는 §6-C 끝) → **3 D 측정** → 4 프리셋 → 6
- **풀**: 전 단계. `SESSION_LIMIT` 블록 분할, 방문 2~3회
- **세션 점검(매 방문)**: 0-B만

## 4. 사용자 흐름

```
매 방문: [0-B 세션 점검] → 플레이
처음/재평가: [0-A] → [0-B] → [1 시작점] → [2 일반 탐색] → [3 D 측정] → [4 조준경] → [5 수직] → [6 복원 카드 + JSON + 잠금]
```
각 단계: ① 인게임에 넣을 값 → ② 훈련장에서 할 일(타이머) → ③ 점수 입력 → ④ 다음 값.

### Step 0-A. 준비 (처음 1회)
- 주 시점(3인칭/1인칭/둘 다), 1인칭 FOV
- 현재 감도 전부(모르면 비움)
- 실제 무기 세팅(예: M416 + 보정기 + 수직 손잡이 + 4배율) — Step 5용
- **훈련장 테스트 위치 메모**(처음 한 번): 일반용 플릭 표적 쌍(거리·간격), 조준경용·4x용·8x용 표적 쌍(배율별 시야가 달라 별도), 360°/180° 기준 지형물, 수직 표적(`V_DIST`)
- 준비물: 테이프, 자
마우스 입력 없음(800/1000 고정 전제).

### Step 0-B. 세션 시작 점검 (매 방문, `T_CHECK`)
순서 고정:
1. Windows: 포인터 속도 6/11, "포인터 정확도 향상" OFF. (관리 프로그램으로 잠겨 있으면 그 사실을 기록하고 진행)
2. 마우스: DPI 800 · 폴링 1000Hz 확인(내 마우스면 체크만, PC방 마우스면 버튼/LED/소프트웨어). **DPI 버튼 조정이 항상 1순위**.
3. 훈련장 입장. 복원 카드 순서대로 **전체 입력** → 체크.
4. **1바퀴 검증**(D가 있을 때만): 복원 카드의 일반값 `G`(= D를 잰 감도)에서 Step 3 절차 1회 → `D′`. `|50·log10(D′/D)| ≤ TOL_SLIDER`면 통과. 불통과면 1회 더 측정해 **둘 다** 불통과일 때만 실패.
5. 실패 → 2번 재확인(800이 아닐 가능성이 가장 큼) → 재측정. 마우스를 800으로 바꿀 수 없으면 예비 환산(§6-D D-2, P3) 적용 후 복원 카드 재입력.

### Step 1. 시작점 (자동)
`S = 현재 일반 감도 ?? 50`.

### Step 2. 일반 감도 탐색 (핵심)
규칙은 §6-B·§6-C만 참조. 흐름:
1. **브래킷**: `S ± W0` 두 값을 테스트(순서 무작위). 한쪽이 **강승**이면 그 방향으로 구간을 확장(이전 구간의 바깥쪽 절반은 유지)해 새 끝값만 테스트. 한 방향으로만, 최대 `SHIFT_MAX`회.
2. **탐색**: 매 회차 도전자 1개를 테스트해 챔피언과 비교. 승패에 따라 구간이 줄거나 챔피언이 바뀐다.
3. **종료**: 구간 폭 ≤ `W_END`, 동률 `TIE_MAX`회, 또는 테스트 수 `T_MAX` 도달. **결과 `G` = 챔피언.**
4. `undo`는 직전 스냅샷 복원(점수·테스트 수 포함). 매 입력마다 폰에 저장.

### Step 3. D 측정 (퀵 포함, P0)
**D의 정의(문서 유일)**: 복원 카드의 일반값 `G`에서, 정면 기준 지형물이 **한 바퀴 돌아 다시 정면에 올 때까지**(360°) 마우스를 직선으로 끌었을 때 테이프 두 점 사이 거리(cm). 패드가 짧으면 180° 지형물 쌍으로 재고 ×2.
절차: 테이프 1 → 직선으로 천천히 끌기 → 같은 지형물 정면에서 멈춤 → 테이프 2 → 자로 측정. `N_MEASURE`회, 평균과 편차 기록.
결과: `D`, `G`, 각도(360/180). 0-B 검증과 cm/360 표시(§6-D D-3)의 기준. **`G`가 바뀌면(재평가 등) D를 다시 잰다**(앱이 경고).
Phase 0의 AHK 카운트 측정은 "지수형 형태 검증", Step 3은 "내 환경 절대값"으로 역할이 다르다.

### Step 4. 조준·조준경·배율
1. 모드: **통일**(토글 ON, 조준·조준경 = 일반) / **분리**(토글 OFF, 프리셋 A / 프리셋 B(Phase 0 후) / 직접). 추천 없음.
2. 퀵: 프리셋 값을 그대로 결과에.
3. 풀 테스트(조준경 → 4x → 8x, 최대 줌 고정, 배율별 표적 쌍):
   - 후보 3개: 현재, 현재−`A_STEP`, 현재+`A_STEP`. 각 1회 테스트(점수 재사용 없음). §6-C M-3(20점)으로 **현재 대비 win 이상**인 후보만 채택, 둘 다 win이면 큰 차. 채택된 후보가 극값이면 같은 방향 1회 추가(최대 1회). tie면 현재 유지.
   - 통일 모드에서 특정 배율을 바꾸면 **분리 모드 자동 전환** + 토글 OFF 안내.
4. 테스트하지 않은 배율은 §6-F 보간. 프리셋 그대로 쓸 때는 보간 비활성.
5. 확정 후 Step 5. 이후 4x를 바꾸면 Step 5 재측정 경고.

### Step 5. 수직 배율
안내: "수직 배율은 모든 조준 모드에 공통 적용되는 것으로 **추정**(Phase 0 확인 후 문구 확정). `V0` 유지가 기본값이고 이 단계는 벗어날 근거가 있는지만 확인한다. 벗어나면 비조준 대각 이동도 왜곡된다."
1. 시작 `V0`. Step 0-A 실제 무기 세팅, 4배율(Step 4 확정값), 거리 `V_DIST`, 서서 사격.
2. 후보 값에서 **첫 `V_SHOTS`발만** 판정: "상탄 / 하탄 / 모임"(세로 분포만).
3. 상탄 → +`V_STEP`, 하탄 → −`V_STEP`. 방향이 뒤집히면 두 값의 중간(입력 단위 반올림)으로 종료. 최대 `V_MAX`회. (적응형 절차이므로 순서 무작위화는 없음)
4. 결과 + 측정 조건(배율, 그 배율 감도, 무기 세팅, 거리).

### Step 6. 복원 카드 + 내보내기 + 잠금

## 6. 상수·규칙 단일 정의 (본문은 이름으로만 참조)

### 6-A. 상수 저장 형식

### 6-B. 일반 감도 탐색 전이표 (정수 슬라이더 공간, 챔피언–도전자 방식)

**입력**: `S`(시작값), `W0`, `W_END`, `SHIFT_MAX`, `TIE_MAX`, `T_MAX`(모드별: `T_QUICK` / `T_FULL` / `T_RE`), `MAXSCORE`(10 또는 20, §6-C), `rng`(결정적 주입).
**상태**: `{ lo, hi, champ, phase: 'bracket'|'search'|'done', shiftDir: -1|0|1, shifts, tieCount, tests, scores: Record<slider, Score>, history: Snapshot[] }`. 생성자가 init 행을 수행한다.
**규칙**: 행은 위에서부터 **첫 일치 행** 적용. 비교 결과는 §6-C M-3로 `win(a) | strong(a) | tie`. `clamp`는 1~100, `round`는 .5 올림. `w = hi − lo`. `canShift(+) ≡ shifts < SHIFT_MAX ∧ shiftDir ∈ {0, +1} ∧ clamp(hi + 2·W0) > hi`(−는 대칭). `undo` = 직전 스냅샷(상태 전체) 복원.

| phase | 상황 | 다음 상태 |
|---|---|---|
| init | — | `lo = clamp(S−W0)`, `hi = clamp(S+W0)`. `lo == hi`면 `champ = lo`, done. 아니면 두 값 테스트(순서 `rng`, tests += 2), 비교 결과를 아래 bracket 행에 적용(`champ` 미정 상태에서는 "champ" 자리를 `lo`로 읽음) |
| bracket | `strong(hi)` ∧ `canShift(+)` | **SHIFT+**: `shiftDir = +1`, `lo = round((lo+hi)/2)`(이전 구간의 안쪽 절반은 유지), `champ = hi`, `hi = clamp(hi + 2·W0)`, 새 hi 테스트(tests += 1), `shifts += 1`. phase = bracket 유지(다음 비교는 `champ` vs `hi`) |
| bracket | `strong(lo)` ∧ `canShift(−)` | **SHIFT−**: 대칭(`shiftDir = −1`, `hi = round((lo+hi)/2)`, `champ = lo`, `lo = clamp(lo − 2·W0)`, 새 lo 테스트) |
| bracket | `win/strong(hi)` (이동 불가 포함) | 이미 `champ`가 있고 `hi ≠ champ`면 `lo = champ`. `champ = hi`. phase = search |
| bracket | `win/strong(lo)` (이동 불가 포함) | 이미 `champ`가 있고 `lo ≠ champ`면 `hi = champ`. `champ = lo`. phase = search |
| bracket | `tie` | `champ` 미정이면 `champ = S에 더 가까운 끝값`(같으면 lo). `champ`가 있으면 구간을 `[min(champ, 새끝값), max(…)]`로 줄이고 `champ = 원점수 높은 쪽`(같으면 기존 champ). `tieCount += 1`. phase = search |
| search | 회차 시작: `w ≤ W_END` ∨ `tests ≥ T_MAX` ∨ `tieCount ≥ TIE_MAX` | phase = done. **결과 = champ** |
| search | 회차 시작(계속) | 도전자 `x` = `[lo, champ]`와 `[champ, hi]` 중 **더 긴 구간의 중점**(`round`; 같으면 `rng`). `x`에 점수가 있으면 재사용(§6-C), 없으면 테스트(tests += 1) |
| search | `win/strong(x)` | `x > champ`면 `lo = champ`, 아니면 `hi = champ`. `champ = x` |
| search | `win/strong(champ)` | `x > champ`면 `hi = x`, 아니면 `lo = x` |
| search | `tie` | `lo = min(champ, x)`, `hi = max(champ, x)`. `champ = 원점수 높은 쪽`(같으면 기존 champ). `tieCount += 1` |
| any | `undo` | history pop(스냅샷 복원) |

**성질(정확한 서술)**: 종료는 보장된다(`tests`가 매 회차 증가하고 `T_MAX`가 있음). 챔피언이 끝값인 회차(브래킷 직후, 동률 직후)는 구간이 줄지 않을 수 있다. 그 외 회차는 반올림을 제외하면 `win(champ)`에서 ≥ 1/4, `win(x)`에서 ≥ 1/3 준다. 동률은 ≥ 1/2 준다. 정수 반올림으로 폭 5→4, 10→8처럼 20%만 줄 수 있다. 한 번 이동한 방향의 반대로는 이동하지 않는다. 구간 안에 점수가 있는 점은 `{lo, hi, champ}`뿐이므로(`W_END ≥ 2`에서) 도전자 점수 재사용은 실제로 발생하지 않는다 — 방어 규칙으로만 둔다.

**vitest 예시** (`MAXSCORE = 10` 임계 §6-C: tie ≤1 / win 2~4 / strong ≥5. `W0 = 10, W_END = 4, SHIFT_MAX = 2, TIE_MAX = 3`. `rng`: 순서는 lo 먼저, 구간 길이 동률은 상위 구간 선택.)

1. **기본 수렴** (`S = 50, T_MAX = 5`): `40→5, 60→7` 차 2 = win(hi) → champ 60, search [40,60], tests 2.
   r1: 긴 구간 [40,60] 중점 50 → `50→8`(tests 3), 8 vs 7 차 1 = tie → [50,60], champ = 원점수 높은 50, tieCount 1.
   r2: w 10 → [50,60] 중점 55 → `55→6`(tests 4), 6 vs 8 차 2 = win(champ), x > champ → hi 55 → [50,55].
   r3: w 5 → 중점 `round(52.5) = 53` → `53→7`(tests 5), 7 vs 8 차 1 = tie → [50,53], champ 50(8 > 7), tieCount 2.
   r4 시작: w 3 ≤ 4 (tests 5 = T_MAX도 성립) → **done, 결과 50**.
2. **이동 후 탐색** (`S = 50, T_MAX = 12`): `40→3, 60→8` 차 5 = strong(hi), canShift(+) → SHIFT+: shiftDir +1, lo `round(50) = 50`, champ 60, hi 80, `80→5`(tests 3), shifts 1. bracket 비교 champ 60(8) vs hi 80(5): 차 3 = win(champ=lo 쪽) → "win(lo)" 행: `lo ≠ champ`(50 ≠ 60)이므로 `hi = champ`? — **아니다**: 이 행은 `lo`가 이긴 경우용이고 여기서 이긴 것은 `champ`(내부점). 따라서 bracket 단계의 SHIFT 후 비교는 search 행으로 처리한다(아래 규칙 보정 참고): `win(champ)`, x(80) > champ → hi = 80 유지 → search [50,80], champ 60.
   r1: [50,60] 10 vs [60,80] 20 → 중점 70 → `70→10`(tests 4), 10 vs 8 차 2 = win(x), x > champ → lo 60, champ 70 → [60,80].
   r2: [60,70] 10 = [70,80] 10 → rng 상위 → 75 → `75→7`(tests 5), 7 vs 10 차 3 = win(champ), x > champ → hi 75 → [60,75].
   r3: [60,70] 10 > [70,75] 5 → 65 → `65→8`(tests 6), 8 vs 10 차 2 = win(champ), x < champ → lo 65 → [65,75].
   r4: [65,70] 5 = [70,75] 5 → rng 상위 → `round(72.5) = 73` → `73→9`(tests 7), 9 vs 10 차 1 = tie → [70,73], champ 70(10 > 9), tieCount 1.
   r5 시작: w 3 ≤ 4 → **done, 결과 70**.
3. **반대 방향 이동 금지, 직전 구간 유지** (`S = 50, T_MAX = 12`): `40→2, 60→8` 차 6 = strong(hi) → SHIFT+: lo 50, champ 60, hi 80, `80→3`(tests 3). 비교 60(8) vs 80(3): 차 5 = strong(champ). champ는 lo 쪽이므로 SHIFT−에 해당하지만 `shiftDir = +1` → canShift(−) 거짓 → search 행 `win/strong(champ)`: x(80) > champ → hi 80 → search [50,80], champ 60. 다음 도전자: [50,60] 10 vs [60,80] 20 → 70. (**50~59 구간이 살아 있다.**)
4. **클램프 붕괴 = 이동 불가** (`S = 95, T_MAX = 5`): lo 85, hi 100. `85→4, 100→9` 차 5 = strong(hi)이지만 `clamp(120) = 100`, 100 > 100 거짓 → canShift 거짓 → `win/strong(hi)` 행: champ 100, search [85,100], tests 2.
   r1: [85,100] 중점 `round(92.5) = 93` → `93→9`(tests 3), 9 vs 9 차 0 = tie → [93,100], champ = 같으면 기존 100, tieCount 1.
   r2: w 7 → [93,100] 중점 `round(96.5) = 97` → `97→6`(tests 4), 6 vs 9 차 3 = win(champ), x < champ → lo 97 → [97,100].
   r3 시작: w 3 ≤ 4 → **done, 결과 100** (85~100 사이를 두 번 봄).
5. **브래킷 동률** (`S = 50, T_MAX = 5`): `40→6, 60→6` tie → champ 미정, S와 등거리 → lo 40, tieCount 1, search [40,60].
   r1: 중점 50 → `50→7`(tests 3), 7 vs 6 차 1 = tie → [40,50], champ 50(7 > 6), tieCount 2.
   r2: w 10 → [40,50] 중점 45 → `45→5`(tests 4), 5 vs 7 차 2 = win(champ), x < champ → lo 45 → [45,50].
   r3: w 5 → `round(47.5) = 48` → `48→6`(tests 5), 6 vs 7 차 1 = tie → [48,50], champ 50(7 > 6), tieCount 3.
   r4 시작: tieCount 3 ≥ TIE_MAX (tests 5 = T_MAX, w 2 ≤ 4 모두 성립) → **done, 결과 50**.

**규칙 보정(예시 2에서 드러난 것, 표에 반영)**: SHIFT 후 bracket 비교는 `champ`(내부점) vs 새 끝값 `x`의 비교이므로 **search 행(`win/strong(x)`, `win/strong(champ)`, `tie`)을 그대로 적용**하고, 그 결과가 `strong(x)`이고 `canShift`가 참이면 SHIFT를 반복한다. 위 표의 bracket `win/strong(hi|lo)` 행은 **init 직후(champ 미정)에만** 쓰인다. 구현에서는 bracket 행을 다음 두 줄로 쓴다:
- `champ 미정`: `strong(끝값) ∧ canShift(그 방향)` → SHIFT; 아니면 `win/strong(끝값)` → `champ = 그 끝값`, search; `tie` → `champ = S에 가까운 끝값`(같으면 lo), tieCount += 1, search.
- `champ 있음(SHIFT 직후)`: `strong(x) ∧ canShift(x 방향)` → `lo/hi = champ`(x 반대편 버림), `champ = x`, SHIFT 반복; 아니면 search 행 적용 후 phase = search.

### 6-C. 지표와 비교 규칙
- **M-1 플릭 점수(P0)**: 두 표적 사이를 플릭하고 **보정 없이 즉시 1발** 사격 → 명중이면 1점. 1테스트 = `FLICK_N`회 × `SETS`세트(퀵 5×2 = 10점, 풀 10×2 = 20점). 세트가 끝날 때마다 폰에 입력.
- **교차 세트와 점수 재사용의 관계(확정)**: **브래킷(init)에서만 교차**(A B A B — 두 후보가 동시에 있으므로). **탐색 회차는 도전자만 2세트 연속** 테스트하고 챔피언 점수는 재사용한다(시간표 §6-H 기준). 알려진 한계: 챔피언 점수가 수 회차 전 것이므로 피로·학습 편향이 있다. 완화: 풀 모드에서 `STALE_ROUNDS`회차 이상 지난 챔피언 점수는 1회 재측정(tests += 1, 새 점수로 교체).
- **M-2 트래킹 점수(P1)**: 이동 표적 `TRACK_SEC`초 명중 수. 수단은 §8 게이트 A.
- **M-3 비교(정수 절대값)**:

| `MAXSCORE` | tie | win | strong |
|---|---|---|---|
| 10 | 차 ≤ 1 | 차 2~4 | 차 ≥ 5 |
| 20 | 차 ≤ 2 | 차 3~6 | 차 ≥ 7 |

- 지표 2개(P1 이후): 지표별 판정 후 합성 — 같은 방향 win+win → win, win+strong → strong, strong+strong → strong; tie+win → win, tie+strong → win; 방향 반대 → tie.
- **M-4 집탄**: 기록만, 가중치 0.
- 노이즈 참고(시뮬레이션, 동일 성능 p = 0.6): 점수 차의 표준편차 ≈ 2.2(10점). 10점에서 동률 51% / 승 ≈ 45% / 강승 ≈ 4%, 20점에서 58% / 39% / 3.4%. 퀵 모드 최종 폭 분포: 5(49%), 10(21%), 2~3(21%), 7~9(7%), 15(3%) → UI에 **"거친 탐색(±3~5, 드물게 ±7)"** 표기.

|---|---|---|
| 조준 | −1 | Phase 0 후 |
| 조준경(1x) | −1 | `50·log10(m_목표 / m_내장)`, `m_목표 = tan(fov_배율/2) / tan(fov_힙/2)` |
| 2x | −2 | 〃 |
| 3x ~ 15x | −4 | 〃 |
A의 Δ가 슬라이더 차이인지는 출처(인벤 분리파) 재확인 항목. 3x = −4는 이 문서의 결정. 프리셋 적용 시 보간(§6-F) 비활성.

### 6-F. 보간
축 `log10(배율)`, 조준경 = 1x. 테스트한 점 사이는 슬라이더 선형 보간 후 정수 반올림. 15x = 8x와 같은 슬라이더 값. 테스트하지 않은 끝은 가장 가까운 테스트 점 값.

### 6-G. 파라미터 표
| 이름 | 값 | 사용처 |
|---|---|---|
| `W0` | 10 | §6-B 초기 반폭 |
| `W_END` | 4 | §6-B 종료 폭 |
| `SHIFT_MAX` | 2 (재평가 0) | §6-B |
| `TIE_MAX` | 3 | §6-B |
| `T_QUICK` / `T_FULL` / `T_RE` | 5 / 12 / 4 | §6-B `T_MAX` |
| `W_RE` | 5 | 재평가 초기 반폭 |
| `STALE_ROUNDS` | 3 (풀 모드만) | §6-C 챔피언 재측정 |
| `FLICK_N` × `SETS` | 퀵 5×2, 풀 10×2 | M-1 |
| `TRACK_SEC` | 15 | M-2 |
| `A_STEP` | 2 | Step 4 |
| `V0` / `V_STEP` / `V_MAX` / `V_SHOTS` | 1.0 / 0.05 / 4 / 10 | Step 5 (단위는 Phase 0 후 조정) |

| `N_MEASURE` | 3 | Step 3 |

### 6-H. 소요 시간 (모드 합계는 여기서만)
테스트 1회 = 설정 변경 왕복 1분(Phase 0 실측 예정) + 플릭(퀵 10회 1분 / 풀 20회 2분) + 입력 0.5분 = **퀵 2.5분 / 풀 3.5분**. 훈련장 입장·로딩 1~3분(Phase 0 확인).

| 단계 | 퀵 | 풀 |
|---|---|---|
| 0-A(처음 1회) | 10 | 10 |
| 0-B(방문당) | 8~10 (+입장) | 8~10 × 방문 2~3회 (+입장 × 블록 수) |
| 2 일반 | `T_QUICK` 5 × 2.5 = 12.5 | `T_FULL` 12 × 3.5 = 42 (+`STALE_ROUNDS` 재측정 ≤ 2회 = 7) |
| 3 D 측정 | `N_MEASURE` 3회 ≈ 8 | 8 |
| 4 조준경 | 프리셋 2 | 배율 3종 × (3 + 최대 1)회 × 3.5 = 최대 42 |
| 5 수직 | — | 변경 1분 + `V_SHOTS` 0.5분, `V_MAX` 4회 = 6 (+이동) |
| 6 복원 카드·내보내기 | 5 | 5 |
| **합계** | **약 50분** (+입장) | **약 2시간 40분** (0-B 3회·입장 포함) → `SESSION_LIMIT` 30분 블록 6~7개, 방문 2~3회 |

## 7. 기술 설계

- **스택**: Next.js 14 App Router, TypeScript, Tailwind 3.4. 서버 코드 없음. `vitest` 추가(현재 테스트 러너 없음). `tsconfig`의 `@/*` alias를 vitest에도 설정(`vite-tsconfig-paths` 또는 alias).
- **라우트**: `src/app/sens/`(라우트 그룹 없음). 루트 `src/app/layout.tsx`(그라데이션 배경, `localStorage.theme` → `dark` 클래스 토글) 상속. `sens/layout.tsx`에 자체 `metadata.title`.
- **테마**: sens UI는 `dark:` 변형을 **쓰지 않음**. `min-h-dvh` 전체 화면 래퍼로 루트 배경을 덮고 **고정 다크 팔레트** 직접 지정. 루트 `dark` 클래스·`theme` 키는 건드리지 않음.
- **클라이언트 경계**: `sens/page.tsx`는 서버 컴포넌트 셸, 위저드 본체는 `'use client'`. localStorage는 mount 이후(`useEffect` + mounted 가드).
- **컴포넌트** `src/components/sens/`: `Wizard`, `StepCard`, `Checklist`, `Timer`, `CandidatePicker`, `ScoreInput`, `MeasureInput`(D), `RestoreCard`, `SessionCheck`, `HistoryList`, `ExportImport`.
- **도메인** `src/lib/sens/`: `constants.ts`, `bisect.ts`(§6-B), `compare.ts`(§6-C, `MAXSCORE` 파라미터), `math.ts`(§6-D), `presets.ts`, `interp.ts`, `storage.ts`, `schema.ts`.
- **타입**: `Score = { flick: number; track?: number }`, `scores: Record<number, Score>`.
- **저장**: 폰 localStorage 단일 키 `sens:state` = `{ version: 1, ... }`. 버전 불일치는 **마이그레이션**(거부 아님). **iOS Safari 대응**: (a) Step 6 JSON 내보내기 필수, (b) "홈 화면에 추가" 안내, (c) 빈 상태면 첫 화면에 "JSON 붙여넣기로 복구".
- **스키마 검증**(`schema.ts`): 슬라이더 1~100 정수, 수직 배율 범위(Phase 0 값), **D 5~300cm**(800 DPI 일반 30~35는 110~140cm, 90은 약 9cm), 날짜 ISO.
- **테스트**: vitest만. `bisect.ts` — §6-B 예시 5건 + 전이표 전 행(도전자 재사용 행은 "도달 불가" 주석) + undo. `compare.ts` — 임계 경계·2지표 합성. `math.ts` — D-1 왕복, D-2 방향, D-3 방향. `interp.ts`. `schema.ts`. E2E 없음.
- **폰 사용성**: 큰 버튼, 타이머 소리(첫 탭 오디오 언락), Screen Wake Lock(미지원 시 안내).

## 8. 검증 계획

### Phase 0 — 실측 스파이크 (구현 전, PC방 1~2회 방문)

**게이트 A — 환경 사실 (결과별 분기 명시):**
- [ ] PC방 재로그인/자리 이동 시 PUBG 감도 설정 보존 여부와 범위 → 사라짐: 복원 카드 P0 유지 / 보존: 복원 카드는 백업, 0-B 3번 "확인만"
- [ ] 훈련장 1세션 제한(`SESSION_LIMIT`)·입장 로딩 시간 → §6-H 블록 재배치
- [ ] 정지 표적 1발 명중 피드백(소리/표시/탄흔) → 있음: M-1 유지 / 없음: M-1을 "플릭 후 표적 안 정지 여부(주관)"로 격하하고 문서 명시
- [ ] 이동 표적 명중 수 수단(카운트 UI / 탄흔 스크린샷 / 인스턴트 리플레이 가능?) → M-2(P1) 활성 여부
- [ ] 표적 명중 후 리셋·쿨다운(연속 플릭 가능?) → `FLICK_N` 세트 설계
- [ ] Windows 포인터 설정이 관리 프로그램으로 잠겨 있는지 → 잠김: 0-B 1번을 "확인·기록"으로, 설정이 7/11 등이면 D-2 유사 환산 필요성 검토
- [ ] PC방 마우스 DPI 확인 수단(LED/소프트웨어/버튼 순환) → 0-B 2번 문구
- [ ] 설정 변경 왕복 시간 실측, 감도 숫자 직접 입력 가능 여부 → §6-H·복원 카드 시간
- [ ] 폰 네트워크, 홈 화면 추가 후 오프라인 로드 → §7

**게이트 B — 설정 구조:**
- [ ] 감도 메뉴 전체 캡처(이름·순서·범위·단위), 수직 배율 단위·범위, **통일 토글 존재·동작**, 가변 배율 적용 값, 인게임 마우스 가속/스무딩 옵션 → §1-1·복원 카드 순서
  - 토글 없음 → Step 4 "통일 모드" 삭제, 프리셋 A/B/직접만
  - 가변 배율이 "현재 줌 배율" 값을 따름 → 보간 축에 3x·4x 값이 실전에서 더 자주 쓰임을 안내
- [ ] ini 필드 목록, 슬라이더 ↔ `LastConverted` 대응표(0~100, 5단위). PC방에서 ini 되돌려지는지

**상수 실측 (분기 포함):**
- [ ] 일반 20/35/50/65/80에서 cm/360(자·테이프, AHK 가능 시 병행) → 지수형 형태 검증. **불일치 시**: D-1 의존 기능(D-3 표시, D-2, 프리셋 B)을 비활성하고 §6-D를 실측 보간표로 교체
- [ ] 일반 50 / 조준경 50 / 4x 50의 cm/360 → 내장 스케일링 역산 → 프리셋 B
- [ ] 1인칭 FOV 80/90/103에서 일반 50의 cm/360
- [ ] 로비 캐릭터 회전으로 1바퀴 대체 가능 여부(UI 드래그라 **거의 불가**로 예상)
- [ ] 훈련장 테스트 위치 확정(일반·조준경·4x·8x 플릭 표적 쌍, 360°/180° 지형물, 수직 표적) → Step 0-A 기본값
- [ ] 앵글 손잡이 삭제 패치노트 출처 → §12

### 자가 테스트
- 퀵 모드 1회 완주 → §6-H 교정.
- 풀 모드를 `SESSION_LIMIT` 블록으로 2~3회 방문에 나눠 완주.
- 다른 자리(PC방 마우스 800 설정)에서 0-B → 1바퀴 검증 통과 여부(2회 규칙).
- `LOCK_DAYS` 후 재평가 1회(iOS면 스토리지 유지 여부 확인).
