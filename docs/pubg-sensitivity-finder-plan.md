# 배틀그라운드 감도 찾기 프로그램 기획서 (v0.1)

> 작성일: 2026-10-18
> 상태: 기획 초안 (구현 전)
> 대상: PC 배틀그라운드(PUBG: BATTLEGROUNDS) 마우스 유저

---

## 0. 한 줄 요약

유튜브·인벤·디시·해외 포럼에 흩어진 "배그 감도 찾는 법"을 **하나의 단계별 위저드**로 묶어,
사용자가 훈련장에서 정해진 테스트를 수행하고 체감을 입력하면
**일반 감도 → 수직 감도 → 조준/조준경 감도** 순으로 자기 감도를 수렴시켜 주는 웹 프로그램.

핵심 차별점은 "숫자를 던져주는 계산기"가 아니라 **검증된 절차를 안내하는 코치**라는 점이다.
계산(cm/360, 배율 변환)은 보조 수단이고, 최종 판단은 항상 사용자의 인게임 테스트 결과로 한다.

---

## 1. 배경: 왜 필요한가

### 1-1. 유저가 겪는 문제
- 감도 관련 설정 항목이 많다: 일반 감도, 수직 감도 배율, 카메라 감도(1인칭/3인칭), 조준 감도, 조준경 감도(레드닷·홀로·2x·3x·4x·6x·8x·15x), 조준경 감도 통일 토글, 차량 감도.
- 커뮤니티 조언이 서로 충돌한다. 예) "조준은 일반-1, 2배율은 -2, 4/8/15배율은 -4" vs "조준·조준경 전부 일반과 동일하게".
- 유튜브 영상은 좋은 방법을 알려주지만 **따라 하다가 중간에 어디까지 했는지 잊는다**. 체크리스트와 기록이 없다.
- "프로 감도 그대로 복사"는 DPI·모니터·패드·손 크기가 달라 그대로 안 맞는다.
- 공식 변환 공식이 없다. PUBG 슬라이더는 지수형이고 FOV 영향도 받아 타 게임 변환기 값이 자주 틀린다.

### 1-2. 기존 도구와 빈자리
| 도구 | 하는 일 | 한계 |
|---|---|---|
| mouse-sensitivity.com | 타 게임 ↔ PUBG 변환, cm/360 | 조준경/ADS 변환은 유료, 영어, 절차 안내 없음 |
| aiming.pro 계산기 | 타 게임 → PUBG 변환 | 변환만. 훈련장 테스트 없음 |
| hitcle.com/aim | 일반 감도 → 배율별 감도 계산 | 3인칭만 지원, 계산만 |
| 보텍스게이밍 "AI 감도 2.0" | DPI 입력 시 일반/수직 감도 추천 | 근거가 불투명, 테스트 절차 없음 |
| Overwolf RazerShot | 마우스 데이터 기반 AI 추천 | 상용, 검증 불가, 데스크톱 전용 |
| 유튜브/인벤 글 | 실제 찾는 절차 | 흩어져 있고 진행 기록·계산 보조 없음 |

→ **"절차(유튜브식) + 계산(변환기식) + 기록/공유"** 를 한 곳에 묶은 한국어 도구가 없다.

## 2. 리서치 정리: 시중에 퍼진 감도 찾는 방법

아래는 조사한 자료에서 반복적으로 등장하는 방법을 분류한 것이다. 프로그램의 각 단계는 이 방법들을 그대로 옮긴다.

### 2-1. 공통 전제 (거의 모든 자료가 동의)
1. **DPI 먼저 고정**(400 또는 800). 프로 90% 이상이 800 이하. 이후 절대 바꾸지 않는다.
2. 마우스 가속 OFF, Windows 포인터 속도 기본(6/11), Raw Input ON.
3. 감도는 **한 번에 하나만**, 작은 폭(1~2)으로 바꾼다.
4. 정한 값은 **최소 1주일 유지**하고 근육 기억을 쌓은 뒤 재평가한다.
5. 기준 단위는 슬라이더 숫자가 아니라 **cm/360**(마우스를 한 바퀴 돌리는 데 필요한 패드 위 거리).

### 2-2. 찾는 순서 (인벤 "감도 찾는 배린이가 봐야 할 인게임 감도 설정 방법")
> 좌우 감도 대략 맞추기 → 수직 감도 조정 → 좌우 감도 섬세하게 조정. 보통 1~2사이클이면 끝.

### 2-3. 일반(좌우) 감도 찾는 테스트
| 출처 | 방법 |
|---|---|
| 인벤 "감도찾기에 대한 모든 노하우" | 구조물 뒤에 앉아 **중앙 집탄**. 탄이 좌우로 불규칙하게 벌어지면 감도 ↓, 잘 모이면 감도 조금 ↑ 해서 비교. 둘이 같으면 **더 높은 감도** 선택 |
| 영어권 가이드 (clip.dor.gg 등) | 이동 표적 **트래킹**: 계속 오버슈트하면 ↓, 못 따라가면 ↑ |
| 영어권 가이드 | 두 표적 사이 **플릭 왕복**: 오버슈트/언더슈트 방향으로 조정 |
| 에임트레이너 커뮤니티 (PSA 방식) | **이분법**: 높은 값/낮은 값 둘 중 편한 쪽을 고르고 범위를 절반씩 좁혀 4~6회 수렴 |
| 보텍스게이밍 | **차량 사격장**에서 좌우 감도 최종 점검 |

### 2-4. 수직 감도 배율 찾는 테스트
| 출처 | 방법 |
|---|---|
| 인벤 "수직감도 맞추기" | 10발 탄창을 쏴서 **상탄이 많이 튀면 +0.05**. 아래로 너무 쉽게 꺾이면 ↓. 조정 폭 0.05~0.1 |
| 보텍스게이밍 | **앵글 손잡이**를 끼워 좌우 반동을 줄인 뒤 검은 원에 집중 사격 → 수직만 평가. 10m/15m 거리 사용 |
| clip.dor.gg | 4배율로 **10/20/30발 버스트**를 쏴 집탄 비교 |
| 프로 통계 (blast.tv) | 프로의 약 60%가 수직 감도 **1.0** 사용. 1.0 시작 후 반동 제어가 잡히면 그대로 둬도 됨 |

### 2-5. 조준(ADS)·조준경 감도
| 출처 | 방법 |
|---|---|
| 보텍스게이밍 | **조준경 감도를 1순위**로. 훈련장 이동 표적을 조준 상태로 좌우 따라가기. 못 따라가면 ↑, 버벅이면 ↓ |
| 인벤 | 통일파: 조준·조준경 = 일반 감도와 동일. 분리파: 조준 -1, 2x -2, 4/8/15x -4 |
| 인벤 2025 영상글 | "감도 통일 vs 감도 분리" 비교. 정답 없음, 성향 문제 |
| clip.dor.gg | 4배율로 표적에 **30초 조준 유지**. 흔들리면 **그 배율만** 낮추기 |
| mouse-sensitivity.com 포럼 (DPI Wizard) | PUBG는 내부적으로 **모니터 거리 수평 100%(MDH 100%)** 로 배율을 스케일링 → 같은 숫자를 넣으면 모든 조준 모드의 체감이 같음. 0% 매칭(초점거리 방식)을 선호하면 배율별로 낮춰야 함 |
| 인벤 "모든 스코프 체감도 동일하게" | 배율별 체감 통일 공식 (위 MDH 개념의 커뮤니티 버전) |

### 2-6. 참고 수치 (시작점용. 정답 아님)
- 커뮤니티 시작 범위 (800 DPI): 일반 45~55, 조준 40~50, cm/360 **30~45cm**
- aiming.pro: 중간 감도 = **22~38 cm/360**
- mouse-sensitivity.com: 경쟁 플레이 권장 **20~80 cm/360**
- 프로 예시: curexi(Virtus.pro, 2025-06) 400 DPI, 일반 45, 수직 1, 조준 45, ADS 33, 2x~15x 전부 39
- 과거 TL/FaZe/TSM 평균 기반 추천: 일반 43

### 2-7. PUBG 감도 수학 (프로그램 계산 엔진의 근거)
- **cm/360 = 2.54 × 360 / (DPI × 카운트당 회전각)**
- **eDPI = DPI × 인게임 감도** (같은 게임 안에서만 비교 가능)
- PUBG 슬라이더(0~100)는 **선형이 아니라 지수형**. GameUserSettings.ini 의 `LastConvertedMouseSensitivity` 값과 슬라이더의 관계로 커뮤니티가 추정한 식:
  - `슬라이더 = 50 × log10(LastConverted / 0.002)` ⇔ `LastConverted = 0.002 × 10^(슬라이더/50)`
  - 즉 **슬라이더 +50 = 10배, +1 ≈ 4.7% 증가**. 슬라이더 50 ≈ 0.02
  - 조준경은 별도 상수를 가짐 (예: 조준경 50 → 0.00429 보고됨)
  - ⚠️ **미검증.** FOV 스케일링이 단순 곱이 아니라는 반론 있음. 공식 문서 없음.
- 따라서 프로그램은 **공식에 의존하지 않고 실측(캘리브레이션)으로 사용자별 상수를 구한다.** 공식은 초기 추정과 배율 간 상대 변환에만 쓴다.
- ini 파일 위치: `%LocalAppData%\TslGame\Saved\Config\WindowsNoEditor\GameUserSettings.ini`

## 3. 제품 정의

### 3-1. 타깃 사용자
1. **배린이**: 감도를 어디서부터 만져야 할지 모름. 기본값 그대로 쓰는 중.
2. **감도 방황러**: 매주 감도를 바꾸며 유튜브 프로 감도를 복사하는 중급자.
3. **세팅 변경자**: DPI/모니터/패드/시점(1인칭↔3인칭)을 바꿔 기존 감도를 환산해야 하는 사람.

### 3-2. 핵심 가치
- **절차**: 유튜브·커뮤니티 방법을 7단계 위저드로 표준화. 각 단계마다 "훈련장에서 무엇을 몇 번 하고, 결과를 어떻게 입력하는지" 명시.
- **수렴**: 이분법으로 4~6회 안에 일반 감도를 결정. 감으로 끝없이 바꾸지 않게 한다.
- **계산**: cm/360 실측, 배율별 상대 변환(통일/분리 모드), 타 게임 감도 → PUBG 시작점.
- **기록·공유**: 결과 카드 + ini 스니펫 + 공유 링크. 1주일 뒤 재평가 리마인더.

### 3-3. 범위 (v1)
- 포함: PC 배그 마우스 감도(일반/수직/조준/조준경/차량 제외), 1인칭·3인칭 모두, 훈련장 기반 테스트, 결과 저장·공유.
- 제외: PUBG 모바일, 콘솔(패드) 감도, 차량 감도, 마우스 입력 자동 측정(별도 데스크톱 앱 필요), 로그인.

## 4. 사용자 흐름 (위저드 7단계)

```
[0 준비] → [1 시작점] → [2 cm/360 캘리브레이션] → [3 일반 감도 이분법]
   → [4 수직 감도] → [5 조준/조준경 감도] → [6 최종 점검] → [7 결과 카드]
```

각 단계는 "① 설정값 안내 → ② 훈련장에서 할 일 체크리스트 → ③ 체감/결과 입력 → ④ 다음 값 제시" 구조로 통일한다.

### Step 0. 준비 (온보딩, 2분)
입력:
- 마우스 DPI (400/800/1600/직접 입력) + "지금부터 고정" 동의 체크
- 시점 (3인칭 / 1인칭) 및 1인칭 FOV (80~103)
- 해상도·화면 비율
- 마우스패드 크기 (소 ~30cm / 중 ~40cm / 대 45cm+ / 직접 입력) → cm/360 상한 계산용
- 플레이 스타일 (근접 돌격 / 밸런스 / 중장거리 저격) → 목표 cm/360 범위
- 현재 감도: 직접 입력 **또는** `GameUserSettings.ini` 업로드(드래그&드롭) → 자동 파싱
- (선택) 다른 게임 감도 (발로란트/오버워치/에이펙스/CS2) → cm/360 변환해서 시작점으로 사용

안내:
- 마우스 가속 OFF, Windows 포인터 속도 기본, Raw Input 체크리스트
- 훈련장 입장 방법, 사용할 무기(M416 + 보정기 + 앵글 손잡이 + 4배율) 안내

### Step 1. 시작점 산출 (자동)
- 입력된 플레이 스타일/패드 크기로 목표 cm/360 범위 결정
  - 근접: 25~35cm / 밸런스: 30~45cm / 중장거리: 40~60cm (패드 길이의 70%를 상한으로 캡)
- 타 게임 감도가 있으면 그 cm/360을 그대로 시작점으로
- 둘 다 없으면 커뮤니티 중앙값(800 DPI 기준 일반 50 ≈ 커뮤니티 시작값)을 시작점으로
- 이 단계의 숫자는 **"임시"** 라고 명확히 표시. Step 2 실측으로 바로 보정.

### Step 2. cm/360 캘리브레이션 (실측, 3분)
목적: 공식 신뢰 문제를 제거하고 **이 사용자의 환경에서 슬라이더 ↔ cm/360 관계**를 확정.
절차:
1. 프로그램이 제시한 일반 감도(예: 50)를 인게임에 입력.
2. 훈련장에서 정면의 기준 지형물을 조준 → 마우스를 **패드 위에서 자로 측정한 거리 X cm** 만큼 한 번에 수평 이동 → 다시 같은 지형물이 정면에 올 때까지 몇 번 반복했는지 또는 회전 각도를 입력.
   - 간단 모드: "X cm 움직였을 때 정확히 한 바퀴 돌았나? (더 돌았다 / 덜 돌았다 / 딱 맞다)" 3지선다로 2~3회 반복해 수렴.
3. 결과로 **실측 cm/360** 과 사용자별 보정 계수를 저장. 이후 모든 변환은 이 계수를 쓴다.
4. 지수형 슬라이더 가정(+1 ≈ ×1.047)으로 "목표 cm/360에 맞는 슬라이더 값"을 역산해 제시.

### Step 3. 일반 감도 이분법 (핵심, 10~15분)
방법: PSA식 이분법 + 인벤 집탄 테스트 + 플릭/트래킹 테스트 결합.
1. 현재 추정값 S를 중심으로 **High = S×1.25(슬라이더 약 +5), Low = S÷1.25(약 -5)** 두 후보 제시.
2. 각 후보로 훈련장 테스트 세트 수행(체크리스트, 타이머 포함):
   - 플릭: 좌우 두 표적 사이 왕복 10회 → "주로 넘어감(오버) / 모자람(언더) / 적당"
   - 트래킹: 이동 표적 좌우 따라가기 15초 → "자꾸 앞서감 / 못 따라감 / 적당"
   - 집탄: 엄폐물 뒤 앉아 20m 표적 중앙 20발 → "좌우로 벌어짐 / 모임"
3. 사용자가 **더 편한 후보**를 선택 → 선택 쪽으로 범위를 절반 좁힘.
4. 4~6회 반복. 범위 폭이 슬라이더 2 이하가 되면 종료. 두 값이 비등하면 **더 높은 쪽** 선택(인벤 규칙).
5. 결과: 일반 감도 확정 + cm/360 표시. 카메라 감도(1인칭/3인칭)는 일반 감도와 동일 권장.

### Step 4. 수직 감도 배율 (5분)
1. 시작값 **1.0** (프로 60%). 무기: M416 + 보정기 + **앵글 손잡이**(좌우 반동 제거 → 수직만 평가), 4배율, 거리 10~15m.
2. 10발 → 20발 → 30발 사격 후 탄착군 입력: "위로 튄다(상탄) / 아래로 꺾인다(하탄) / 세로로 잘 모임"
3. 상탄 → **+0.05**, 하탄 → **-0.05**. 폭은 0.05~0.1.
4. 2~3회 반복해 확정. "세로 집탄은 모이는데 좌우가 벌어진다"면 Step 3로 되돌아가라는 분기 안내.

### Step 5. 조준·조준경 감도 (10분)
1. 모드 선택:
   - **통일 모드(기본·추천)**: 조준경 감도 통일 ON, 조준·모든 배율 = 일반 감도. (PUBG 내부 스케일링이 MDH 100%라 체감이 이미 통일됨)
   - **분리 모드**: 조준경 감도 통일 OFF. 프리셋 A "커뮤니티형"(조준 -1, 2x -2, 4x~15x -4) / 프리셋 B "0% 초점거리형"(배율 FOV 비율로 계산, 고배율이 더 느려짐) / 직접 입력
2. 테스트 (배율별 반복: 레드닷 → 4x → 8x 순, 나머지는 보간):
   - 이동 표적 조준 트래킹 15초 → "못 따라감 ↑ / 버벅임·앞서감 ↓"
   - 4x로 표적 30초 조준 유지 → 흔들리면 **그 배율만** 1~2 낮추기
3. 결과: 조준 감도, 레드닷/홀로/2x/3x/4x/6x/8x/15x 각 값. 테스트 안 한 배율은 선택 모드의 규칙으로 자동 채움.

### Step 6. 최종 점검 (5분)
- 차량 사격장에서 이동 표적 좌우 감도 최종 확인 (보텍스게이밍 방식)
- 훈련장 1v1 또는 일반 매치 3판 후 "너무 빨랐다 / 느렸다 / 괜찮다" 입력
- **1주일 고정 권고** + 재평가 리마인더(브라우저 알림 또는 공유 링크 재방문 안내)

### Step 7. 결과 카드
- 모든 설정값 표 (일반/수직/카메라 1·3인칭/조준/조준경 8종/통일 토글)
- 실측 cm/360, eDPI, 패드 사용 비율(한 바퀴에 패드의 몇 %를 쓰는지)
- **프로 분포 비교**: "당신의 cm/360은 프로 상위 N% 저감도" 식 퍼센타일 (출처·날짜 명시)
- 복사 버튼: 인게임 입력 순서 가이드 / `GameUserSettings.ini` 스니펫
- 공유 링크 (`/sens/r/{slug}`) → 링크나무 프로필에 카드로 꽂을 수 있게 연동
- 히스토리: 이전 측정과 비교 (재측정 시)

## 6. 계산 엔진 설계

```
입력: dpi, slider(일반), 사용자 보정계수 k (Step 2 실측), fov, 시점
기본식:
  degPerCount(slider) = k × 0.002 × 10^(slider/50)       // k=1 이면 커뮤니티 추정식
  cm360(slider)       = 2.54 × 360 / (dpi × degPerCount)
  slider(cm360목표)   = 50 × log10( 2.54×360 / (dpi × cm360목표 × k × 0.002) )
상대 변환 (배율):
  Δslider(배수 m)     = 50 × log10(m)                      // 감도 m배 ↔ 슬라이더 변화
  0% 초점거리 매칭    = m = tan(fov_scope/2) / tan(fov_hip/2)  ← 배율별 실측 FOV 테이블 필요
  통일(MDH 100%)      = Δslider 0 (게임이 알아서 스케일)
```
- 모든 상수는 `constants/pubg.ts`에 모으고 **"추정/실측/출처"** 태그를 붙인다.
- Phase 0에서 실측값으로 상수를 교정하고, 실측과 공식의 오차가 10%를 넘으면 공식 대신 **실측 보간 테이블**을 쓴다.

## 7. 기술 설계 (가정: 이 레포의 스택 재사용)

- **프레임워크**: Next.js 14 App Router, TypeScript, Tailwind (현재 링크나무와 동일)
- **라우트**: `src/app/sens/` (위저드), `src/app/sens/r/[slug]/` (결과 공유), `src/app/api/sens/` (저장/조회)
- **컴포넌트**: `src/components/sens/` — `Wizard`, `StepCard`, `TestChecklist`, `Timer`, `BisectPicker`, `ResultCard`, `ProPercentile`
- **도메인 로직**: `src/lib/sens/` — `math.ts`(순수 계산), `bisect.ts`(수렴 상태 머신), `iniParser.ts`, `presets.ts`, `pros.json`
- **저장**: MongoDB Atlas 컬렉션 `sens_profiles` `{ slug, dpi, fov, pov, general, vertical, aim, scopes{}, cm360, k, createdAt, history[] }`
- **상태**: 진행 중 데이터는 localStorage, 완료 시에만 서버 저장 (개인정보 없음, ini 파일은 서버로 보내지 않음)
- **반응형**: 모바일 우선. 사용 시나리오가 "PC로 게임 + 폰으로 위저드 보기"이므로 폰 화면 최적화가 중요.
- **다크모드**: 기존 ThemeToggle 재사용. 게임 중 사용을 고려해 다크 기본.
